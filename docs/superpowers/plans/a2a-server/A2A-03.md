# A2A-03 — Journal-Backed Task Projection and Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans after G1 scheduling and A2A-02 acceptance.

**Goal:** Produce truthful bounded snapshots and ordered public event streams for real Runs, including a stable replay cursor.
**Epic / requirements:** G1; R1,R2,R3,R4,R6.
**Architecture:** Read committed Run/Journal state through core-owned callbacks. Reuse existing assistant-text projector/digest verification; project only sanitized status, user/assistant text and safe artifact metadata. A standard subscription emits a current snapshot then tails; replay emits only missed public events and tails on the same stream.
**Tech Stack:** Go; existing Journal iterator and Run/Sessions stores; no A2A SDK in core.
**Spec:** G0-approved design and [shared contract](index.md).
**Baseline:** main `3c4ed66826f5a40fd27dba0d9e208c55240a5955`.

## Global Constraints

No raw Journal event, reasoning, tool args/result, approval ID/token, secret, policy explanation or filesystem path leaves the Host. A MessageStore row can lag the Journal and cannot alone prove a committed reply. SSE disconnect closes only the iterator/stream, never cancels the Run. Replay guarantees **retained public events** only; Session deletion invalidates that history explicitly.

## Review Focus

Multiple public projections from one Journal seq must have distinct ordered cursors; filtered private entries must not cause false gaps; append during snapshot→tail and replay→tail must not be lost; terminal during disconnect must replay terminal; lagging/corrupt assistant projection must not be emitted as successful output.

## Prerequisites and interfaces

Consume A2A-02 scoped receipt owner, bounded list and actual `RunID`/`SessionID` plus the frozen A2A-01 Port fields. Produce `TaskHost` implementations for Get/List/Cancel/Subscribe/Replay and the Host-approved public event type consumed by A2A-05/06. The cursor is a versioned, task-scoped `(runID, journal_seq, public_event_ordinal)` value. Its encoded representation and typed errors are frozen at G0; cursor data never bypasses owner verification. Streams have one ordered Journal-backed read position; wakeup signals are hints, not event truth.
