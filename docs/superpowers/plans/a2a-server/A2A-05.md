# A2A-05 — Official SDK Standard Server Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans after G1 is accepted and the owner schedules G2.

**Goal:** Make a selected `projectvivy/a2a-server` module answer the supported A2A 1.0 standard operations with real Vivy tasks.
**Epic / requirements:** G2; R1,R2,R4,R5.
**Architecture:** Implement the official SDK's `a2asrv.RequestHandler` independently over the optional TaskHost and pass it to `a2asrv.NewJSONRPCHandler`. Use SDK types/serialization/errors/standard SSE, but never its `NewHandler`/TaskStore/executor/listener. Derive the Card from compiled/enabled endpoint and actual capability evidence.
**Tech Stack:** Go module `plugins/a2a-server`; official `github.com/a2aproject/a2a-go/v2` pinned in the plugin only; Vivy v1 Module/Recipe.
**Spec:** G0-approved design and [shared contract](index.md).
**Baseline:** main `3c4ed66826f5a40fd27dba0d9e208c55240a5955`.

## Global Constraints

Module `projectvivy/a2a-server`, source `plugins/a2a-server`, Provider `vivy.a2a`, Port `std/channel@v1`, Consumer `core/channel-host@v1`, effective Grant `channel.a2a`. Standard SDK client need not implement replay B. No cross-import of core Runtime/Policy/Journal in the plugin; no default/lite Recipe mutation. Unsupported push/config/extended-card methods return the SDK's typed unsupported error, not an accidental nil response. A2A is not a Face.

## Review Focus

Request `taskId` continuation must explicitly fail after access check; text-only Parts validation rejects unsupported media; stream starts with standard Task snapshot; reconnect to terminal `SubscribeToTask` rejects as spec requires; Card never advertises unmounted endpoint/skill; no SDK packages in non-A2A artifact.

## Prerequisites and interfaces

Consume A2A-03 concrete TaskHost snapshots/events/errors and A2A-04 exact Host HTTP mounts and verified identity. G0 SDK probe must establish the complete `a2asrv.RequestHandler` method set at the pinned version (GetTask, ListTasks, CancelTask, SendMessage, SendStreamingMessage, SubscribeToTask, push methods, GetExtendedAgentCard). The plugin maps SDK A2A IDs to real Run/Session IDs; no shadow map.
