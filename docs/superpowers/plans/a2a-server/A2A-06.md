# A2A-06 — Optional Exact Event Replay Extension Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans only after the owner explicitly adopts the one-extension Issue amendment, accepts G1, and schedules G2.

**Goal:** Let an enhanced client recover every retained public committed event after its saved cursor, including a terminal event missed while disconnected.
**Epic / requirements:** G2; R3,R4,R6.
**Architecture:** Keep official SDK standard JSON-RPC/SSE untouched. Add one explicitly versioned, opt-in SSE operation to the **same Host-owned listener**; it calls `TaskHost.ReplayTaskEvents`, which atomically catches up and tails Journal-backed public events. Cursor is stable across process restart and has no authority absent Host authentication.
**Tech Stack:** Go `net/http` SSE framing; existing plugin A2A model conversion and Host public event stream; no new event store or runtime dependency.
**Spec:** G0-approved `docs/architecture/A2A-TASK-EVENT-REPLAY.md#v1`, the [shared contract](index.md), and accepted A2A-03/05 revisions.
**Baseline:** main `3c4ed66826f5a40fd27dba0d9e208c55240a5955` + accepted predecessor revisions.

## Global Constraints

Extension is optional (`required: false`) and documented in Agent Card only while mounted. Standard A2A `SubscribeToTask` still sends current snapshot first and rejects terminal tasks. The B extension has **no initial snapshot**, no approval action and no new Run creation. One active connection handles catch-up and tail; no separate replay endpoint plus standard resubscribe handoff. Never advertise exactly-once transport delivery: the client deduplicates repeated IDs and persists cursor with local event state.

## Review Focus

Reconnect after terminal, disconnect at last catch-up event, multi-ordinal projection, filtered private Journal rows, duplicate delivery, cursor from another task/future/unknown version, Session deletion, revoked token and too-large replay window must each yield the frozen behavior without a false exact-replay claim.

## Prerequisites and interfaces

Consume A2A-03 `ReplayTaskEvents(ctx, TaskReplayQuery)` and public `TaskEvent{Cursor,...}` plus A2A-04 Host authentication/limits/mount and A2A-05 SDK A2A event mapper/Card. Extension contract frozen in A2A-00: `POST /a2a/extensions/task-event-replay/v1`; JSON request contains `taskId`, optional `contextId` and exclusive `after` cursor; response is SSE `id: <cursor>` and `data: <public A2A event record>`; error before stream begins follows the documented HTTP error envelope. **Explicit** `after` is authoritative for enhanced clients, so `Last-Event-ID` never silently overrides it. Empty `after` means from first surviving public event. Wire schema and error statuses are finalized in G0, not chosen ad hoc by this Story.
