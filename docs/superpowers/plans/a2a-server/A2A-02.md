# A2A-02 — Atomic External Admission and Task Ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans after the owner schedules G1 and A2A-01 is accepted.

**Goal:** Resolve every authenticated A2A message to one durable Vivy Run and Session, with bounded owner-scoped lookup.
**Epic / requirements:** G1; R1,R2,R4,R6.
**Architecture:** Reuse Runtime's primary admission and `ContinuityStore` mechanics; extend the **same transaction** with one small external admission index. A module never sees the database, caller principal is Host-injected, and a stable message ID is checked before provisional session creation.
**Tech Stack:** Go; SQLite/PostgreSQL; paired embedded core migrations.
**Spec:** G0-approved design and [shared contract](index.md).
**Baseline:** main `3c4ed66826f5a40fd27dba0d9e208c55240a5955` (refresh migrations before work).

## Global Constraints

No plugin-owned DB, shadow TaskStore, separate Run allocator, or `BeforeStart`-only receipt. Paired additive migration must use the next actual shared number, not a number reserved by this plan; keep released SQL immutable. If the production backend cannot atomically write Run, message, startup event and external index, **stop** rather than accepting post-commit repair as idempotency.

## Review Focus

First request lacking `contextId` retried after lost response; same external key with changed payload; two concurrent retries creating provisional Sessions; uncertainty at SQL Commit; deletion followed by reuse of the same message ID; cross-principal run ID guessing. Tests must prove these, not just an in-memory mutex.

## Prerequisites and contracts

Consume A2A-01 Task DTOs and G0 scope/digest rules. Proposed core-owned interface in `internal/storage` (name finalized in G0): `CommitChannelTaskAdmission(ctx, admission) (receipt, newlyCommitted, error)`, `FindChannelTaskAdmission(ctx, channelID, principalID, messageID) (receipt, found, error)`, `ListChannelTaskAdmissions(ctx, channelID, principalID, contextID, page) (items, next, error)`, and `GetChannelTaskOwner(ctx, runID) (receipt, error)`. `receipt` carries digest, original Session/Run IDs, timestamps and owner; plugin never handles storage types. Runtime is entered through an app-injected callback to `Service.RunWithOptions`, with no alternative Runner or direct raw plugin import.
