# S2: retained originals and shared interaction index Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Every eligible LIFE interaction is durably recoverable once, with authorized cross-session ordering.
**Architecture:** Keep originals in current Journal/messages/artifacts; add a metadata-only
subject index and retention binding through core Storage migrations.
**Tech Stack:** Go, SQLite/PostgreSQL, existing Journal/ToolOperationStore/BlobStore.
**Spec:** [design revision 3, C2 and singleton binding](../../specs/2026-10-15-issue-58-unified-context-design.md).
**Epic/requirements:** Retained experience / R2,R6.
**Baseline/status/predecessors:** [index](index.md); S0 accepted C2 and the #66 consumer seam.

## Global Constraints

GPT-6.1 Sol High. No new transcript DB, duplicate body table or plugin DDL. Paired
append-only migrations only. Subject is not ProfileID/session/role. Source reads are
authorized, not a shortcut around #57. Coding context strategy stays unchanged.

## Review Focus

- Tool output is currently shortened before operation persistence: capture before that boundary.
- Duplicate timestamps, concurrent seals and retries must never skip/double-count sources.
- Fork/rewind changes views, not the historical experience cursor.
- List removal must not cascade-delete retained Journal/artifacts.
- Core identity cannot open a second empty Recap directory after a profile/path change.
