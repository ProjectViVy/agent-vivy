# S4: governed Recap UI and tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Humans and authorized agents inspect and manage the complete actual Recap through one owner API.
**Architecture:** Existing cognitive ActionHost/ToolHost adapters expose C1; existing
`vivy/memory` UI consumes them, keeping dirty drafts separate from committed state.
**Tech Stack:** Go Module/Port, React/TypeScript, UI SDK, Vitest/Playwright.
**Spec:** [design revision 2, C4 wireframe and C1](../../specs/2026-10-15-issue-58-unified-context-design.md).
**Epic/requirements:** Governed management / R4,R6.
**Baseline/status/predecessors:** [index](index.md); S1 stable tested C1 owner.

## Global Constraints

GPT-6.1 Sol High. No UI-local authority, full schemas by default, main-chat redesign,
persona automatic pinning, or #66 work. UI follows existing Module/SDK contracts and
Chinese/English catalog ownership. S4 may build before S2/S3, but exact source
navigation and runtime activation semantics require S5 integration before acceptance.

## Review Focus

- A stale save must keep the draft even when a background refresh arrives.
- Empty clear differs from physical deletion and requires truthful activation timing.
- Restore is a new revision with current coverage, not historical replay.
- Hidden tools must remain inaccessible to unauthorized workers even by guessed name.
- Full-text view must show actual owner data, including oversized/legacy unavailable state.
