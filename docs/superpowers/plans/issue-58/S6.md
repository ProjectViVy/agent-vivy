## Global Constraints

GPT-6.1 Sol High for implementation/fixes; independent reviewer does not review only
their own changes. Centralize user product acceptance at this stage. No merge,
deployment, user data mutation or backend switch is implied. Use disposable stores.
Every claimed result names the same Vivy candidate SHA, Laputa pin and Generation.

## Review Focus

- Successful model text can hide a missing Recap in the actual provider request.
- Multi-generation summaries can lose corrections/promises or invent facts.
- Mock transport and cross-compile are not installed UI/Windows proof.
- A later fix invalidates earlier candidate evidence; never aggregate mixed SHA greens.
- Mentle contract tests do not replace the owner's installed DIVA acceptance.

## Rollback and stop conditions

Disable new LIFE admission and its projection consumer, retain original sources,
Recap/history and installed previous compatible artifact. Never load a v3 directory
with an old writer, downgrade schema or delete evidence to make rollback pass.
Stop for mismatched artifact/pin, missing real provider/Windows environment,
unresolved scope/identity conflict, nonempty legacy replacement request or failure
of source retention. Report verified versus unverified outcomes plainly; do not merge
or deploy unless separately authorized after this reviewable result.
