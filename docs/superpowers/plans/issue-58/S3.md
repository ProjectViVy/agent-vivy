# S3: unified admission and safe compaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Actual LIFE provider requests contain one committed Recap plus exact shared recent originals; compaction never retires uncommitted evidence.
**Architecture:** Adapt the existing Service admission and Eino summarization hooks,
using S1 owner CAS and S2 ordered sources. No second engine or scheduler.
**Tech Stack:** Go, pinned Eino v0.9.13, current ContextHost/model observation.
**Spec:** [design revision 1, C1–C3](../../specs/2026-10-15-issue-58-unified-context-design.md).
**Epic/requirements:** Unified continuity / R3,R6.
**Baseline/status/predecessors:** [index](index.md); accepted S1 C1 and S2 C2.

## Global Constraints

GPT-6.1 Sol High. All Eino imports remain inside runtime/provider. LIFE selection is
trusted/persisted and cannot derive from Face alone. Coding context behavior remains
unchanged. No legacy history drop/read fallback/session summary for selected LIFE.
WORLD and worker implicit persona/Recap/history injection remain forbidden.

## Review Focus

- Current history-read errors fall back to empty history; LIFE must fail closed.
- A large current interaction cannot be retired before seal; pause on capacity shortage.
- Full schemas and Chinese text invalidate bytes/4 as a safe capacity bound.
- Eino callback/event failure can occur after Finalize committed; reload receipt/head.
- Clear can race suspended/checkpointed runs; no stale snapshot resumes.
