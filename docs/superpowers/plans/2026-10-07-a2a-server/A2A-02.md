# A2A-02 — Atomic Native Admission Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or explicitly selected superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admit one owned native task per accepted external message, including concurrent sends without a context and retries after a lost response.

**Architecture:** Extend native primary admission with core-owned scope/ownership/receipt records in the same transaction. Reuse existing prompt, Mask, workspace and Run launch authority; never forward to the incomplete continuity branch or use BeforeStart as an atomic receipt hook.

**Tech Stack:** Go 1.26.4, existing Service/Eino engine, paired SQLite/PostgreSQL migrations.

**Spec:** [Design section 6](../../specs/2026-10-07-a2a-server-design.md), baseline `58d1143` plus adopted G0 revision.

**Epic / requirements:** E1 / R2, R5. **Status/dependencies:** [index](index.md#epics-and-story-authority).

## Global Constraints

Apply [package constraints](index.md#global-constraints). IDs are 1–256 UTF-8 bytes without control characters; input has 1–16 text parts and at most 64 KiB text, further constrained by native serialized-event limits. Never claim SQL atomicity across FrozenCore/filesystem stores. The G0 preparation contract must contain exact native cleanup symbols before Task 2 can start.

## Review Focus

RF1/RF2: lookup before busy/quota/allocation; body changes conflict; deleted or foreign identity cannot recreate or adopt work. The existing `MASK-CONTINUITY-SNAPSHOT` gap is not closed by this feature.

### Task A2A-02.1: Core receipt schema and admission transaction

**Files:** Create (proposed) `internal/domain/channel_task.go`, `internal/storage/channel_tasks.go`, `internal/storage/sqlite/channel_tasks.go`, `channel_tasks_test.go`, `internal/storage/postgres/channel_tasks.go`, `channel_tasks_test.go`, paired `internal/storage/migrations/{sqlite,postgres}/036_channel_tasks.sql`; modify existing backend `runs.go`, migration conformance tests and `internal/domain/event.go`; create `schemas/events/payloads/channel.task_admitted.json`. Allocate the next unused paired migration number if 036 has been taken at kickoff.

**Interfaces:** Produce the following internal boundary, owned here and consumed by later Stories. It contains no SDK/protocol types. `ChannelTaskCommit` embeds existing `PrimaryRunCommit` and the fields specified in design 6.1; `ChannelTaskAnswerCommit` is defined/implemented in A2A-03, not stubbed with a false success here.

```go
// package domain, proposed
type ChannelTaskScope struct { InstanceKey, PrincipalID string }
type ChannelTaskInput struct {
    Scope ChannelTaskScope
    MessageID string
    SessionID SessionID
    RunID RunID
    Parts []string
}
type ChannelTaskReceipt struct {
    Scope ChannelTaskScope
    MessageID, Operation string
    InputHash [32]byte
    SessionID SessionID
    RunID RunID
    QuestionID string
    AcceptedSeq EventSeq
    CreatedAt int64
    DeletedAt *int64
}
// package storage, proposed
type ChannelTaskCommitResult struct {
    Receipt domain.ChannelTaskReceipt
    Events []domain.RunEvent
    NewlyCommitted bool
}
type ChannelTaskRunQuery struct {
    Scope domain.ChannelTaskScope
    SessionID domain.SessionID
    AfterRunID domain.RunID
    Limit int
}
type ChannelTaskRunPage struct {
    Runs []domain.Run
    NextRunID domain.RunID
    HasMore bool
}
```

Both backends implement these exact methods; introduce `ChannelTaskStore` with the four available methods now and add its answer method in A2A-03:

```go
FindChannelTaskReceipt(context.Context, domain.ChannelTaskScope, string) (domain.ChannelTaskReceipt, bool, error)
CommitChannelTask(context.Context, ChannelTaskCommit) (ChannelTaskCommitResult, error)
GetChannelTaskOwner(context.Context, domain.ChannelTaskScope, domain.RunID) (domain.SessionID, error)
ListChannelTaskRuns(context.Context, ChannelTaskRunQuery) (ChannelTaskRunPage, error)
```

### Task A2A-02.2: Native preparation, admission ordering and launch

**Files:** Create (proposed) `internal/runtime/channel_tasks.go`, `channel_tasks_test.go`; modify existing `internal/runtime/service.go`, `isolation.go`, `payloads.go`, and only the additional native preparation files explicitly frozen by A2A-00.2. Do not begin this task with an unspecified persona cleanup interface.

**Interfaces:** Produce `(*Service).SubmitChannelTask(context.Context, domain.ChannelTaskInput) (domain.ChannelTaskReceipt, error)` for new tasks. Add internal `RunOptions.ChannelTask *ChannelTaskAdmission`, carrying validated scope/message/hash/parts and optional candidate Session, through the existing RunWithOptions path. Existing `Service.Cancel(domain.RunID) bool` remains the cancellation authority. TaskID-targeted answer dispatch is supplied in A2A-03.

- [ ] **Step 1:** Write `TestChannelTaskMissingContextConcurrentRetry`, `TestChannelTaskReplayBeforeBusyAndQuota`, `TestChannelTaskNewSessionPreparation` and the runtime part of `TestChannelTaskAdmissionFaultMatrix`. Assert:

```text
two identical missing-context sends => one Session, one primary Run, one launch, same IDs
accepted retry while busy / cap full / after completion => original receipt
new distinct message while owned context busy => retryable rejection, no queue
candidate defaults + empty revision-zero Mask + prompt snapshot => match committed Session
definite loser => only its provisional resources released
uncertain commit => receipt resolution before cleanup; no replacement Run
HTTP cancellation after commit => native Run continues
```

- [ ] **Step 2:** Run `go test ./internal/runtime -run 'TestChannelTask' -count=1 -v`. Expect failures for the missing admission path, not a missing model credential; use existing deterministic model/test infrastructure.
- [ ] **Step 3:** Implement this precise ordering using the adopted preparation lifecycle:

```text
validate IDs/text and encoded event size
derive fixed-field channel-task/v1 hash, including original optional selectors
lookup authorized receipt before busy checks, quota, allocation or prompt work
prepare candidate/native prompt under existing admission gates
commit via ChannelTaskStore; if conflict/busy races an identical winner, re-read receipt
if NewlyCommitted: publish returned events, register/launch existing native execution once
otherwise: return winner; clean only definite uncommitted resources
```

Reject incompatible Continuity, GoalRound, BeforeStart, HumanAdmission and arbitrary attachment options. Native `Service.Run` startup remains the only execution path. No automatic replay of effects after ambiguous launch/restart.

- [ ] **Step 4:** Repeat focused tests with `-race -count=1`; run backend concurrency tests too. Inject crash/commit boundaries without sleep-based timing. Expect one launch in normal concurrent admission and honest native failure where restart cannot prove safe resumption.
- [ ] **Step 5:** Commit runtime admission: `feat(runtime): admit external tasks through native primary runs`.
