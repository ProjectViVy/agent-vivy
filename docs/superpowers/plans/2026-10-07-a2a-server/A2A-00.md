# A2A-00 — Evidence and G0 Adoption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or explicitly selected superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce enough reproducible evidence to freeze the transport and native preparation contract without silently weakening issue #2.

**Architecture:** Probe the official transport with a minimal custom RequestHandler in an isolated test module. Investigate existing native preparation ownership; retain the single design as the place where approved decisions are recorded.

**Tech Stack:** Go 1.26.4; `github.com/a2aproject/a2a-go/v2 v2.6.0`; existing native SQLite/PostgreSQL/cognitive code.

**Spec:** [Design sections 1, 6.2, 8, 12–14](../../specs/2026-10-07-a2a-server-design.md), baseline `58d1143`.

**Epic / requirements:** E0 / R7. **Status/dependencies:** [index](index.md#epics-and-story-authority).

## Global Constraints

Apply [package constraints](index.md#global-constraints). This Story does not start a production endpoint, implement TaskHost or change issue acceptance without the owner's decision. Probe code under testdata is never a runtime input or shipped provider.

### Task A2A-00.1: Reproducible official-client probe

**Files:** Create (proposed) `sdk/testdata/a2a-probe/go.mod`, `go.sum`, `handler_test.go`, `compatibility_test.go`; create `docs/research/2026-10-07-a2a-sdk-probe.md`. Read the pinned SDK's `a2asrv/handler.go`, `jsonrpc.go`, `a2aclient/factory.go`, `jsonrpc.go`, `internal/sse/sse.go`.

**Interfaces:** Consume the 11-method `a2asrv.RequestHandler`, `a2asrv.NewJSONRPCHandler` and `a2aclient.NewFromCard`. Produce a checked compatibility report, exact dependency sums and reproducible test source, not a production Host interface.

- [ ] **Step 1:** Write `TestA2ACustomHandlerOfficialClient(t *testing.T)` with the following subtest assertions. Define test-only RequestHandler methods with exactly the pinned signatures; unsupported push/card methods return the standard SDK errors.

```text
compile: custom handler satisfies all 11 RequestHandler methods
send: returnImmediately returns the handler's original task/context IDs
stream: first item is a Task; following status/artifact order is preserved
interrupt: input-required and auth-required each close the current stream
terminal: subscribe is unsupported; GetTask still returns terminal truth
validation: unsupported version/content/tenant/extension is rejected
middleware: private context marker survives; stripped bearer never reaches handler
errors: pre-header RPC error and post-header stream error decode with official client
limits: oversized snapshot/frame is an error; no fake successful truncation
```

- [ ] **Step 2:** Run `go -C sdk/testdata/a2a-probe test ./... -run TestA2ACustomHandlerOfficialClient -count=1 -v`. Expect a relevant red failure before the minimal custom handler is complete; missing Go/network setup is a blocked environment, not a valid red result.
- [ ] **Step 3:** Implement only the test handler and HTTP test server, using official SDK codecs/client. Pin v2.6.0; retain generated sums. Demonstrate the absence of a standard durable cursor rather than inventing one. Do not construct `NewHandler`, `AgentExecutor`, `TaskStore` or a second execution queue.
- [ ] **Step 4:** Repeat the command. Expect every named subtest to pass without skips. Record version/commit, raw commands, decoded event sequence and any default-SDK behavior requiring explicit adapter validation. If the pin has changed at kickoff, audit the delta and revise the design before adoption.
- [ ] **Step 5:** Commit probe source and report: `test: probe official A2A custom handler compatibility`.

Produce an exact candidate-session preparation/cleanup contract with native owner, permitted paths, symbols and orphan-recovery fixture. No distributed transaction is proposed.

- [x] **Step 1:** Trace the actual calls for a missing Session, successful admission, definite rollback, concurrent losing candidate, ambiguous commit and process restart. Record which writes belong to core SQL, filesystem and FrozenCore storage.
- [x] **Step 2:** Verify whether existing native cleanup can remove only the losing provisional candidate without touching the accepted winner. Keep A2A-02 blocked if any outcome lacks a concrete native owner/test.
