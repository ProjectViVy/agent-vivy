# A2A-06 — Protocol Module and Artifact Acceptance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or explicitly selected superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the explicitly selected A2A Module and prove the complete official-client/native-runtime path, including physical omission.

**Architecture:** The plugin maps official SDK requests/events onto the completed TaskHost and supplies an http.Handler through ListenHandler. Host controls transport lifecycle; Recipe/Assembly supplies the removable Module and artifact evidence.

**Tech Stack:** Go 1.26.4, A2A 1.0, `a2a-go/v2 v2.6.0`, public Module/Channel SDK, existing vivy-sdk pack/Inspect/conformance.

**Spec:** [Design sections 4, 7–13](../../specs/2026-10-07-a2a-server-design.md), baseline `58d1143` plus adopted G0 revision.

**Epic / requirements:** E2 / R1, R6–R9. **Status/dependencies:** [index](index.md#epics-and-story-authority).

## Global Constraints

Apply [package constraints](index.md#global-constraints). Keep official SDK imports/dependency inside the optional Module and isolated test probes. The plugin may not import native app/runtime/storage, even to simplify an integration test. A real-client smoke must run against composed native Service or the packed executable, not only a fake TaskHost.

## Review Focus

RF1/RF3/RF4/RF5: wire validation occurs before admission, blocking timeouts do not acknowledge a working task as finished, stream interruption semantics are exact, card claims are truthful and oversized results never start replacements.

### Task A2A-06.1: Official transport, mapping and discovery

**Files:** Create (proposed) `plugins/a2a-server/go.mod`, `go.sum`, `handler.go`, `mapping.go`, `card.go`, `settings.go`, `handler_test.go`, `mapping_test.go`, `card_test.go`. Reuse A2A-00 probe assertions; remove duplicated probe implementations once their evidence is retained and all cases have a single maintained home.

**Interfaces:** Private `requestHandler` implements all 11 pinned `a2asrv.RequestHandler` methods. It consumes `channel.TaskHost` and `channel.TaskServiceInfoHost`. `newRequestHandler(tasks channel.TaskHost, info channel.TaskServiceInfoHost) *requestHandler`; `newHTTPHandler(handler *requestHandler) http.Handler` mounts the official JSON-RPC handler and public card. `mapTaskSnapshot(channel.TaskSnapshot) (*a2a.Task, error)` and `mapTaskError(error) error` are the only protocol mapping boundary; other conversion helpers remain private.

- [ ] **Step 1:** Port `TestA2ACustomHandlerOfficialClient` and add mapping table tests for every design 7/11 state/error. Assert user role/text-only parts, history -1/0/omitted/positive semantics, output negotiation, message-ID retries, context consistency, unsupported tenant/extensions/referenceTaskIds and no metadata-based privilege/model/policy selection. Invalid requests must show zero Submit calls.
- [ ] **Step 2:** Run `go -C plugins/a2a-server test ./... -run 'A2ACustomHandler|Mapping|Card' -count=1 -v`. Expect missing adapter/mapping behavior to fail after local module setup.
- [ ] **Step 3:** Implement the custom RequestHandler plus `a2asrv.NewJSONRPCHandler`, using official codecs/framing and G0-proven validation behavior. SendMessage submits once; nonblocking returns after durable receipt; blocking waits for terminal/interrupted state or returns a safe timeout without cancellation. Stream sends begin with the snapshot, end on both interrupted states and use full stable artifacts. Four push methods return push-not-supported; extended card returns unsupported-operation. The card advertises only configured compiled capabilities, bearer scheme and safe skills.
- [ ] **Step 4:** Repeat all official-client probe cases. Validate `append=false`, `lastChunk=true`, snapshot reconciliation, terminal GetTask after unsupported SubscribeToTask and no wire cursor extension. Enforce pre-write size limits on encoded SDK values. Oversize GetTask may remain unavailable; list with artifacts omitted is the supported smaller view, not an invented GetTask flag.
- [ ] **Step 5:** Commit adapter/mapping: `feat(a2a): map official protocol transport onto native TaskHost`.

### Task A2A-06.2: Module composition and real native smoke

**Files:** Create (proposed) `plugins/a2a-server/vivy-module.yaml`, `module_v1.go`, `module_test.go`, `artifact_test.go`, `recipes/a2a.vivy.yml`, `sdk/internal/a2a_artifact_test.go`, `internal/app/a2a_tasks_test.go`; modify existing `internal/app/facehost_test.go` and `internal/channelhost/approval_test.go` for local-control regressions. Native ID/cancellation/approval assertions must not import the official SDK into production Core.

**Interfaces:** Export only normal Module entrypoints `New() module.Module`, `NewProvider() channel.ChannelProvider`. Provider Definition ID is `a2a`; its constructed instance implements Channel Instance plus live `ListenHandler() http.Handler` and CapabilitySource. Start prepares handlers, Stop releases them, Send returns typed unsupported. Native app tests prove task/run and context/session identity; the isolated plugin official-client test drives the packed process over HTTP and imports no internal packages.

- [ ] **Step 1:** Write `TestA2AModuleComposition`, `TestA2AApprovalIsLocalOnly` and `TestA2AArtifactClientSmoke`. Required assertions:

```text
selected Module descriptor => projectvivy/a2a-server, correct Port/consumer/grant
Start => ready handler without plugin socket; Host owns actual bind
official client => discover card, send tool-bearing task, receive committed output/terminal
retry original message ID => same task/context and no second native admission
ordinary question reply => same Run; /approve or metadata => no remote authorization
local authorized approval => continues; no Face => native expiry/failure/cancel
cancel target => target only; client disconnect => accepted work continues
```

- [ ] **Step 2:** Run `go -C plugins/a2a-server test ./... -run TestA2AModuleComposition -count=1 -v`, then `go test ./sdk/internal -run TestA2ASelectedAndOmittedArtifacts -count=1 -v` once the test driver exists. Expect real composition/transport assertions to fail before wiring; a skipped smoke is not an accepted result.
- [ ] **Step 3:** Build the explicit Recipe from the existing native host modules plus only the required A2A Module/grant. Use the compiler's explicit source closure; do not add A2A to default Assembly or root production dependency closure. The SDK artifact test starts an isolated scripted OpenAI-compatible model server, packs the selected binary, writes temporary native config and runs the binary with the existing `VIVY_CONFIG` path. The plugin's `TestA2AArtifactClientSmoke` receives test-only endpoint/token variables from that driver. A test-only environment variable is never a product flag or live model provider. The scripted model must request an actual governed tool before final text; echo-only success is insufficient.
- [ ] **Step 4:** Run the real client against that binary, retaining safe native Run IDs/correlation evidence and final artifacts. The driver must reject absent/skipped smoke results and clean processes/temporary stores. Separate native tests assert exact DB/Journal identity and no extra launch; the plugin never queries the core database. Verify local Face approval and no-Face expiry on the actual composed path as well as unit tests.
- [ ] **Step 5:** Commit Module and native smoke: `feat(a2a): compose optional server module and native client smoke`.
