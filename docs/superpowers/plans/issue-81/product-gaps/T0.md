## Produced contract and review focus

`just toolkits-e2e` invokes `node scripts/toolkits-e2e.mjs` and runs lifecycle then accessibility suites sequentially. Proposed env inputs `VIVY_TOOLKITS_E2E_BACKEND_PORT` / `VIVY_TOOLKITS_E2E_UI_PORT` default to 18787/3015; validate integers 1–65535 and reject equal endpoints before launch. Pass UI port through existing `VIVY_UI_PORT` and backend URL through `VIVY_BACKEND_ADDR`. Set explicit binary path through existing `VIVY_TOOLKITS_E2E_BINARY`.

Use `process.platform` for vivy/vivy.exe and native pnpm invocation, `spawn` argument arrays rather than shell-concatenated executable/config paths. Allocate fresh SDK output below lane-local .workspace, pack `recipes/default.vivy.yml` and Inspect it. Explicit external binary overrides require the matching inspected artifact/source identity recorded; do not silently reuse stale default output. The native gate uses its own backend and `reuseExistingServer:false`; existing opt-in manual external-backend mode is not the reproducible gate.

Review path spaces, Windows suffix, stale artifacts, occupied/invalid ports and leaked child processes. Keep one worker/fresh data root and never terminate another lane's process.
