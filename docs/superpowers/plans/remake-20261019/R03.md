# R03: Shared contracts and migration intake plan

**Goal:** Fix the shared boundaries that feature work consumes, once the real target is known.
**Architecture:** One integration owner; feature-owned typed deltas; serialized dependency/schema/generation edits.
**Spec:** [Design](../../specs/2026-10-19-remake-design.md). **Immediate inputs:** R01 retained hunk map and R02 accepted core B. **Status:** Blocked.

R03 establishes the common integration spine and applicable contracts for the first released batch. It does not require every future feature contract to be solved at once: Toolkit D07, Recap data conversion or a missing Skill dependency blocks only the affected lane. Per-lane unresolved contracts stay on that lane card after the common spine is accepted.

Proposed planning outputs: `contracts.md`, `migration-map.csv`, and a `batch-<lane>.json` receipt per released batch. They are not generated with guessed APIs now.

- [ ] For each retained feature list consumed/produced exact target types, methods, action IDs, errors and supported failure states; identify one owner per fact.
- [ ] Select one compatible published Laputa closure for the chosen Recap/Skill/cognitive batches, matching all module requirements and source lock. Do not force those pins on unrelated features.
- [ ] Map historical SQL 036-046 and BML donors to B's formats; distinguish fresh-target install, released old-main upgrades, intermediate supported sources and unsupported sources. Do not allocate target numbers until B and the preceding accepted batches are fixed.
- [ ] Reserve fresh paired SQLite/PostgreSQL migration IDs serially under core Storage ownership; review conversion fragments and immutability/source-format policy. No feature-local DDL or old migration rewrite.
- [ ] When Toolkit is selected, resolve D07 for Toolkit using owned ArtifactID/release/config-revision consent, without custom application hash authority.
- [ ] Freeze source Module/Port/Recipe/generator changes; the integrator produces Assembly/UI projections from source. Keep native dependency/TLS/Git integrity and build-time source pins separate from retired custom digests.
- [ ] Specify revision/expected-input conflicts using the actual accepted no-hash core representation. Do not reintroduce BaseHash under another name or weaken stale-write rejection.
- [ ] Refine each released lane's first sub-batch into executable tasks with exact target paths/signatures, meaningful failing test, verification commands and rollback/data support. Add only demonstrated missing feature prerequisites to dag.json and revalidate.

Acceptance: released batch has no unresolved interface/ownership/data/default-selection decision. Unselected batches remain Blocked; no whole-system contract redesign is a prerequisite for an unrelated simple fix.
