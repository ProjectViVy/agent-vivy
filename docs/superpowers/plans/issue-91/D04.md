## Consumed and produced contracts

Consumes D02 completion and D03 durable exact inputs/typed outcomes. Produces direct durable outcome -> Eino ToolMessage -> next request while **retaining nudge coaching**. The owner explicitly requires nudge; no no-op middleware or ordinary-error-only substitute satisfies this Story.

Keep `nudgeWindow.record(toolName, argsJSON, result, errMsg string) int`; replace `[]uint64`/FNV with a ten-entry bounded window of exact four-string tuples, preserving current canonical input and result/error matching. Store immutable string references, not additional unbounded copies. Preserve current ten-step window, thresholds 3/5, request-order tie break, successful-call advancement, refusal/corrective templates, maximum 1024-byte reminder and context-budget skip behavior. Do not add content hashing, permanent blacklist or automatic tool retry.

Advisory state receives completed typed outcomes directly from the actual tool boundary, after mandatory durable effect completion; it does not decide effect ownership. Use the pinned native `adk.WithAfterToolCallsHook` for the after-tools boundary and existing model middleware for injection; order results by the native batch's call IDs. Remove the event-consumer Register/Complete/Seal acknowledgment dependency, not advisory state. Pre-claim refusal remains refused/not_executed and feeds coaching without a fictitious execution start.

Keep `tool.nudge` and its existing schedule-before-injection persistence contract: append once before the model sees a notice, retries reuse the notice without another scheduling event, failure preserves the original error. A change making that persistence best effort needs separate G1 approval. Approval/question resume, steering and cancellation must not consume stale notices or repeat effects. No change to required Journal/final-message/terminal/budget ownership is authorized merely by retaining nudge.
