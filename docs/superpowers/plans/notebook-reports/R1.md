# R1 — Bounded Manual Report Generation Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: use `superpowers:executing-plans` for sequential execution, or `superpowers:subagent-driven-development` only if selected by the owner. Use checkboxes to track implementation steps.

**Goal:** Generate daily/weekly/monthly reports through one sealed workflow, preserve evidence and feedback, and publish safely alongside editable notebook content.
**Architecture:** R0 authority binds four effects: collect, narrate, validate-render, persist. Storage owns source reads and atomic publication; one tool-free Eino call supplies optional narrative. Report generations hold immutable provenance, never execution state.
**Tech Stack:** Go, INOFY, Eino v0.9.13 via existing provider/runtime adapter, SQLite/PostgreSQL, module control actions.
**Spec:** [Design](../../specs/2026-10-09-notebook-reports-design.md), sections 5–10, 16.
**Requirements:** RP-01, RP-02, RP-03, RP-04, NB-03, NB-04.
**Status/dependencies:** [Package index](index.md).
**Global Constraints:** Inherit index. No report-specific Agent loop, arbitrary user prompt, external research, evolution evidence import or model retry/repair loop.
**Review Focus:** incomplete source coverage; user assertions versus evidence; cancellation versus fallback; publication races; persisted output before workflow acknowledgement.

## Contracts owned here

Complete `internal/reportcontract/types.go` with `Period`, `Window`, `ReportSettings`, `FactBundle`, `SourceRef`, `FeedbackSnapshot`, `GenerationProvenance`, `ReportResult`. These are domain-facing DTOs; runtime owns prompt/model conversion. Facts and source refs are distinct from user comments/human edits. A source ref identifies exact authorized message/event/revision and digest; a comment never becomes a source-event ref.

`ReportSettings` owns period, series identity, IANA timezone, target section, existing provider/model selection, enabled schedule fields, revision and admitted resource limits. One existing CronJob per `(scope, period)` is the persistent authority, including disabled/manual-only rows. Add its typed `report` payload and CAS revision in this Story so R2 and R3 share one contract; R3 adds dispatch, updates and schedule behavior. Manual defaults create/read the same disabled row through Storage; no second config table or settings.yaml copy. Changing config revision changes attempt identity, not an existing period document's identity.

N1's GeneratedCommit becomes a closed DTO containing trusted Run/operation identity, target key, admitted target head/version, generated Markdown and immutable provenance. Storage transaction inserts revision + generation + output receipt + conditional head update. Its receipt binds Run ID and node operation key. First publication creates the entry/head together; it does not expose an empty reserved report. Only the admitted generated writer can invoke this path.

**Eino capability check:** Use `components/model.BaseChatModel.Generate` once with a fresh tool-free model from existing resolution; inspect `ToolCallingChatModel.WithTools` and provider adapter to avoid mutating shared instances. No tools/ADK runner/second graph. Context deadline and token budget derive from admitted limits bounded by existing Run/provider limits. INOFY still owns durability. Record exact inspected pinned APIs in implementation evidence.

**Pinned reference:** DIVA `dev` at `c565bb245cc920258d7f8c7fcd9544fbba545af7`, report generator/fact_bundle/validate/period and rhythm/monthly modules (spec section 16). Reuse daily aggregation/missing-date fallback ideas, not Rust types, evolution `EvidenceRef`, file storage or its no-activity error. Source inspection is not evidence of Vivy integration.
