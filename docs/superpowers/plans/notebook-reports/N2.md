# N2 — Optional Notebook Module and Trusted Actions Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: use `superpowers:executing-plans` for sequential execution, or `superpowers:subagent-driven-development` only if selected by the owner. Use checkboxes to track implementation steps.

**Goal:** Expose real scoped notebook operations through ActionHost and the existing three note tools; physically omit the capability when unselected and prevent notebook content entering automatic learning.
**Architecture:** New T1 `vivy/notebook-core` provides `core/notebook-service@v1`, `std/control-action@v1` and `std/tool@v1`. App is the sole factory consumer. ActionHost grants a typed owner-bound facade; ToolHost retains tool execution authority. No public Storage Port.
**Tech Stack:** Go, module v1 compiler/Assembly, ActionHost, ToolHost, durable message/operation metadata.
**Spec:** [Design](../../specs/2026-10-09-notebook-reports-design.md), sections 3, 4, 7, 10, 13, 16.
**Requirements:** NB-01, NB-02, NB-05, NB-06, NB-07, RP-04.
**Status/dependencies:** [Package index](index.md).
**Global Constraints:** Inherit index and `.agents/skills/vivy-plugin`. Both proposed internal Ports stay unsupported until their own seven artifacts pass. This Story owns only the notebook Port.
**Review Focus:** forged human origin; foreign scope; response loss; physical module omission; provenance after replay/compaction.

## Contract and capability ownership

Extend N1's `internal/notebookcontract/ports.go` with `Factory`, `FactoryInput`, `Bundle`, `ScopedActions` and `ActionHost`. Factory input is the N1 narrow Store and a trusted scope resolver; output is operations plus an idempotent close handle. No raw DB, runtime Service, Eino or untyped locator crosses this seam.

```go
type Factory func(context.Context, FactoryInput) (Bundle, error)
type ActionHost interface {
    controlaction.Host
    Notebook() (ScopedActions, error)
}
```

`ScopedActions` exposes named notebook methods, accepts only section-7 DTOs and captures scope/actor in the host binding. `ScopeResolver` resolves Home or the canonical workspace of a server-authorized Session; it never accepts a raw path or arbitrary scope ID from a provider. Existing face/connection identity is transport attribution, not a persistent notebook owner. Unknown/foreign IDs fail `not_found` before revealing versions.

Factory cardinality is 0..1, Generation lifecycle, T1-only, sole consumer App. Public SDK `controlaction.Host` does not grow a notebook method. A closed/unarmed/mismatched provider handle fails explicitly. No additional UI Grant. Direct authenticated human content changes are admitted through a narrow trusted origin rule in the existing policy path; explicit deny rules remain decisive. Agent action/tool requests retain frozen Run policy, budgets and approval checks.

**Eino capability check:** Keep existing ToolHost/runtime adapter. This Story adds no model or memory algorithm. Provenance classification belongs before durable ToolOperation admission and in message projections, not a new Eino middleware that silently learns or rewrites content.
