> For agentic workers: REQUIRED SUB-SKILL: use `superpowers:executing-plans` for sequential execution, or `superpowers:subagent-driven-development` only if selected by the owner. Use checkboxes to track implementation steps.

**Goal:** Replace the demo notebook with durable section/document editing, revisions, comments, conflict recovery and export against N2 actions.
**Architecture:** Retain `vivy/notebook` UI identity and host route frame. Module-owned components use the existing module-action client and backend capability projection. Content authority stays on the backend.
**Tech Stack:** React, TypeScript, existing MasterDetail, react-markdown, remark-gfm, Vitest and Playwright.
**Spec:** [Design](../../specs/2026-10-09-notebook-reports-design.md), sections 7–8, 13.
**Requirements:** NB-02, NB-03, NB-04, NB-05, NB-06.
**Status/dependencies:** [Package index](index.md).
**Global Constraints:** Inherit index, `ui/AGENTS.md` and plugin skill. Resolve its required `oil-frontend` skill before UI implementation (see the index environment gate). No shell-store import, raw RPC implementation, new editor dependency or localStorage content authority.
**Review Focus:** dirty-buffer preservation; same-key retry; cross-scope navigation; accessible empty/error states; real split UI and module omission.

## Consumer contract

N2's action IDs/JSON schemas/errors own the wire contract. Use `createModuleActionClient` from `sdk/ui/src/action-client.ts` with the host-provided RPC, including its existing 1 MiB limit. Module-local TypeScript types mirror only the sealed DTOs needed by the page; tests compare representative serialized requests to backend schema fixtures.

Editor state is `(entryID, loadedVersion, baseRevisionID, localDraft, pendingOperationKey)`. Retrying the same save retains both key and payload; editing after a failed attempt starts a new operation only after resolving an unknown outcome. A stale CAS never clears the draft. Scope changes clear selection only after unsaved-change confirmation and invalidate scoped request state. Report buttons remain absent until R1/R2; revision origin labels already work for stored report fixtures.
