# R0 — Trusted Report Workflow Authority Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: use `superpowers:executing-plans` for sequential execution, or `superpowers:subagent-driven-development` only when selected by the owner. Use checkboxes to track implementation steps.

**Goal:** Admit a report as a trusted root workflow in the existing Service, with sealed capabilities, durable deduplication and trusted reporting provenance.
**Architecture:** Extend existing workflow admission/RunStore, not Service count. New T1 `vivy/reports` supplies `core/report-service@v1`; App consumes its typed factory. Reporting is an internal root case, never a new arbitrary-root-workflow RPC.
**Tech Stack:** Go, INOFY pinned at `71e2c9bbe47d`, existing Storage/Journal/observer and generated module binding.
**Spec:** [Design](../../specs/2026-10-09-notebook-reports-design.md), sections 3, 9, 10, 16.
**Requirements:** RP-01, RP-03, RP-04, NB-05.
**Status/dependencies:** [Package index](index.md).
**Global Constraints:** Inherit index. R1 supplies production node effects and public report actions. R0 must not advertise successful report generation through placeholder effects.
**Review Focus:** no synthetic Agent parent; duplicate admission across processes; rejected node authority; report exclusion before first event; omitted/closed capability.

## Interfaces and authority decisions owned here

Create `internal/reportcontract/{types,ports}.go`, importing only domain-facing contracts. Define `ReportRequest` (period, explicit window selector, operation key, optional target), trusted `AdmissionContext` (resolved scope, actor/origin), `ReportAdmission` (Run ID, created/rejoined/busy), `Factory`, `FactoryInput`, `Bundle`, `ScopedActions`. R1 fills the closed settings/source/output DTOs and action schemas. No Eino, raw SQL, arbitrary graph, model prompt or tool inventory enters this boundary.

```go
// Internal, reached through an authenticated owner-bound facade.
func (s *Service) StartReport(context.Context, reportcontract.AdmissionContext,
    reportcontract.ReportRequest) (reportcontract.ReportAdmission, error)
```

Use one hidden control Session per notebook scope, persisted by Storage, as the existing admission lock owner. It has a trusted purpose, no synthetic user message and no Agent parent. Root report Run: kind workflow, depth 0, empty parent, root ID=self, purpose=report. Hidden Sessions are excluded from chat/sidebar/report sources but included in recovery/administration. Ordinary child workflows retain parent-authorizer and child-ledger semantics.

Extend WorkflowRevision's immutable admission identity with `AdmissionNamespace`, `RequestDigest`, `TargetKey` and root-purpose data. Normal child namespace derives from parent Run; report namespace derives from control Session/scope. Preserve the existing lookup wrapper for child callers; add a typed namespace lookup for reports. Request digest covers the caller's stable semantic request, not newly collected comments/config/as-of. Retry looks up the existing key before collecting fresh dynamic input. Same key/different request -> idempotency conflict; distinct key/same active target -> existing Run/busy. Target reservation lives in this authority, not a report job table.

**Eino/INOFY capability check:** Inspect local pinned `inofy/types.go` (`NodeDescriptor`, `NodeExecutor.Execute`, `RunStore.Commit/Load`, `Bindings`). Reuse its fence/checkpoint execution; Vivy owns policy/scope. R0 invokes no model. R1 reuses Eino `BaseChatModel.Generate`; no Agent/compose workflow replaces INOFY durability.
