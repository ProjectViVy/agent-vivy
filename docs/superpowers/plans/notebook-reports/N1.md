# N1 — Durable Scoped Notebook Content Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: use `superpowers:executing-plans` for sequential execution, or `superpowers:subagent-driven-development` only when selected by the owner. Use checkboxes to track implementation steps.

**Goal:** Persist scoped sections, editable Markdown, immutable revisions, comments and retry receipts with SQLite/PostgreSQL parity and repeatable legacy import.
**Architecture:** Core Storage owns schema and atomic operations. A dependency-free internal contract carries typed content DTOs; N2 will bind the service to Hosts. Generated publication is specified here but implemented with provenance in R1.
**Tech Stack:** Go, database/sql, existing migration runner, shared backend conformance.
**Spec:** [Design](../../specs/2026-10-09-notebook-reports-design.md), sections 4–7, 12, 16.
**Requirements:** NB-02, NB-03, NB-04, NB-06, NB-07.
**Status/dependencies:** [Package index](index.md).
**Global Constraints:** Inherit index. Allocate paired migration IDs at execution; current baseline ends at 035. Never rewrite released migrations. All notebook query/mutation keys include trusted scope.
**Review Focus:** acknowledged versus unknown saves; stale writers; cross-scope IDs; tombstones/system roles; reopen/import parity.

## Contract owned here

Create `internal/notebookcontract/types.go` and `ports.go`. They import neither Storage nor runtime/Eino. Export typed DTOs for every notebook action in spec section 7. Use named requests, not `map[string]any` dispatch. JSON requests contain no authoritative scope/actor/provenance fields. Internal `MutationContext` carries `ScopeID`, `Actor`, `OperationKey`, and canonical request digest; only trusted consumers can construct it in N2.

```go
type Store interface {
    ListEntries(context.Context, ScopeID, ListEntriesRequest) (EntryPage, error)
    GetRevision(context.Context, ScopeID, GetRevisionRequest) (RevisionView, error)
    SaveEntry(context.Context, MutationContext, SaveEntryRequest) (MutationReceipt, error)
    // Remaining named section/entry/comment operations follow spec section 7.
}
type SaveEntryRequest struct {
    EntryID string
    ExpectedVersion int64
    BaseRevisionID string
    Title string
    Markdown string
}
```

`MutationReceipt` includes resource ID, resulting version, revision ID where applicable and original outcome. Errors have stable codes from the spec plus current-version metadata; use `errors.Is`/typed errors internally. Body bytes count UTF-8 bytes, not runes. Metadata pagination is stable `(updated_at,id)` with a cursor bound to scope/filter; query in SQL with `limit+1`. Revision bodies are fetched individually, never embedded in list pages.

`GeneratedWriter.CommitGenerated(ctx, GeneratedCommit) (GeneratedReceipt,error)` is a reserved internal seam. N1 defines snapshot head/version, operation key, generated revision reference and outcome (`promoted`/`candidate`) fields; R1 owns its implementation and provenance DTO. Do not expose a generic caller-selected `origin=generated` write path now.

## Task 2 — Add schema and atomic content operations

**Create:** `internal/storage/notebook.go`, `internal/storage/sqlite/notebook.go`, `internal/storage/postgres/notebook.go`, paired `internal/storage/migrations/{sqlite,postgres}/<next>_notebook_content.sql`.
**Modify:** `internal/storage/contracts.go`, `internal/storage/migrations/manifest_test.go`, `internal/storage/migrations/runner_test.go`.

- [ ] Add `NotebookStore` to the Engine contract through the narrow contract interface. Keep SQL helpers within each existing backend; no new database connection or package initialization DDL.
- [ ] Implement logical tables `notebook_sections`, `notebook_entries`, `notebook_revisions`, `notebook_comments`, `notebook_mutations`. Encode composite scope ownership, unique active system-role identities, revision/head integrity and receipt uniqueness in constraints where possible.
- [ ] Implement receipt lookup before current-state checks. In one transaction validate ownership/version/base, insert immutable revision, CAS head/version, and insert receipt. Canonical digest excludes mutable transport metadata but includes every semantic request field and operation kind.
- [ ] Implement all named CRUD operations from spec section 7. Comments retain immutable version history or equivalent historical rows so generation can refer to old versions; active/resolved/deleted state transitions use CAS. Revision adoption creates a new human revision referencing the selected revision.
- [ ] Enforce 256 KiB body, 16 KiB comment and 100-row page bounds. Empty title/invalid UTF-8/invalid cursor fail before writes. Do not inherit the old 4 KiB tool bound into the content store.
- [ ] Seed Notes/Daily/Weekly/Monthly role sections per scope through an idempotent Storage transaction. Stable role IDs survive display-title changes. Reject deletion of a populated section or a required system-role section; reject moving into a deleted/foreign section. Entry tombstones retain revisions/comments; restore does not resurrect a deleted parent silently.
- [ ] Run Task 1 GREEN plus `go test ./internal/storage/migrations ./internal/storage/sqlite ./internal/storage/postgres -count=1`. Require real PostgreSQL execution; record skipped tests as missing parity evidence.
