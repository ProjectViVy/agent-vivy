# CH-C4 summary — `plugins/telegram` direct-message text (ABI template)

Date: 2026-08-30. Branch: `feat/channel-c4` (based on `feat/channel-c3` @
`3ae5f17`).

## What changed

### Added `plugins/telegram/` (independent Go module, first real ear)

- `go.mod`: `module example.com/vivy/plugins/telegram`; direct dependencies
  are only `agent-vivy v0.0.0` (replace `../..`) +
  `github.com/mymmrac/telego v1.10.0` (same generation as picoclaw, stable
  long-poll API); `go.sum` was generated by `go mod tidy`.
- `vivy-plugin.json`: seam `channel`, grants
  `["channel.poll","secret.read"]`, `channel.transport: "poll"`,
  `max_message_runes: 4096`, no tools.
- `plugin.go`: `Plugin` implements both `plugin.Plugin` and
  `plugin.Channel` (compile-time assertions).
  - `Start`: strict settings decode (fail-closed) → resolve
    `settings.token_env` through `env.Secret` (the Host pins Secret to
    the envelope token_env, so the two must match) → `telego.NewBot` (injectable
    HTTP client / base_url / proxy) → explicit `GetMe` authentication (telego
    v1.10 only format-checks the token and lazily executes getMe; without mandatory
    authentication, a permanently retrying deaf ear would remain) →
    `UpdatesViaLongPolling` (`AllowedUpdates: ["message"]`, filtered
    server-side) → normalize each message in the poll goroutine, then
    `PublishInbound`.
  - Inbound policy: only "direct message + human sender + plain text". Ignore edited
    messages / channel posts / groups and supergroups / missing sender / the bot's own
    messages (echo-loop prevention) / `SenderChat` proxies / non-text.
    `Sender = "telegram:<from id>"`.
  - `Send`: send each text part as plain `sendMessage` (no parse_mode)
    and return the platform message id; `ReplyTo/TopicID` are unsupported in
    this slice; non-text parts are skipped; non-numeric ChatID is fail-closed.
  - `Stop`: cancel long polling and wait for the poll goroutine to exit
    (bounded by the input ctx); idempotent and safe before Start. `bot/cancel/done`
    are not rewritten after Start returns (the CH-C3-N2 Send/Stop race surface is
    closed on the adapter side).
  - Error visibility: retain telego's default logger (writes stderr and automatically
    redacts the token); a failed `PublishInbound` only drops the message and
    does not kill the ear (the Host log owns the audit surface).
- `settings.go`: `Settings{token_env, base_url, proxy}`, strict JSON decode
  (DisallowUnknownFields + reject trailing documents); missing settings decode as zero
  value, and Start is fail-closed when `token_env` is missing.
- `plugin_test.go`: all tests use an `httptest` loopback fake Bot API, with
  no real Telegram network.
- `README.md`: Chinese product documentation (scope, policy boundaries,
  configuration example, packaging method, and dependency discipline).

### Kernel-wide envelope hardening (`internal/channelhost`; common surface only,
no TelegramSettings)

- **New ABI (the only ABI change in this slice)**: `plugin.ChannelEnv` gains
  `Settings() json.RawMessage`. The Host recursively converts the envelope's
  `channels.<name>.settings` (opaque `yaml.Node`) through yaml→any→json
  and passes it to the adapter; omitted or null → `{}`. Contract §11's
  "settings are decoded by the channel plugin" previously lacked a transport path;
  this completes it rather than creating a new seam.
- `hostEnv.Secret` pins the envelope `token_env` (CH-C3-N2): an empty
  declaration → Secret always errors; a mismatched name → error; error messages contain
  only the name and result, never the value.
- Added `env_test.go` covering both sides.

### pack fixes independent-module closure (CH-C2 carry-over gap)

- Added `parseRequireLines` (single-line + parenthesized require blocks +
  comments + preserve `// indirect`), `parseModulePath`; merge the
  plugin require closure (skip the product's own require, deduplicate same name/version,
  coexist with version drift under MVS) and merge complete go.sum lines.
- **Mechanism upgrade**: C2's "put go.mod into -overlay" approach necessarily fails for
  plugins with third-party dependencies—readonly `go build` requires go.mod to
  exactly match the MVS result (the telego closure raises indirect versions such as
  x/crypto), and in practice `go build -mod=mod` refuses to update an overlaid
  go.mod. It now uses `go build -modfile <tmp>/pack.mod -mod=mod`: the merged
  copy lives in a temporary directory, the toolchain completes and builds against the
  temporary pair, and the real go.mod/go.sum receive zero writes.
  `-overlay` remains limited to zz_register.go.

## Explicitly not done

- Webhook, group triggers, media, command menus, MarkdownV2/HTML, and voice: none
  implemented.
- Zero changes to `internal/config` (no TelegramSettings); no touch to
  `internal/runtime`; product `go.mod`/`go.sum`/`zz_register.go`
  remain byte-for-byte unchanged.
- Reply threads, topics, and outbound 4096-rune limit handling (new TODO entry
  CH-C4-N1).
- Verify manifest fixtures (CH-C2-N1): an SDK verifier surface, untouched in this
  slice, remains OPEN.
- Delivery durability / `chanin_*` retention policy (the remaining Host-side
  item from CH-C3-N1).
