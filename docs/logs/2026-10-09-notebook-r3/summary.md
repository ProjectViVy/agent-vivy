# R3 — Scheduled generation and fenced recovery

## Delivered

- **Settings write authority** (`vivy.reports.settings.write` → `ScopedActions.WriteSettings` → `AdmissionPort.WriteReportSettings` → `Service.WriteReportSettings` in `internal/runtime/report_settings.go`): trusted input contract `ReportSettingsWrite{Period,ExpectedRevision,Timezone,SectionID,Provider,ModelID,Enabled,ScheduleExpr}` — validation order: capability present, actor reference, period, operation_key, expected revision > 0, IANA `time.LoadLocation`, enabled ⇒ non-empty `ValidateCronExpr` schedule, section exists and not deleted (`validateReportSection`), model selection declared by the provider catalog (`validateReportModelSelection`). The commit goes through `CommitReportSettings` — a receipt-backed mutation on the shared `notebookStore.mutate` machinery (`kind = report.settings`) that CASes the cron-row revision inside the same transaction that writes the durable mutation receipt. Replay re-reads the committed row so the returned revision is authoritative; a divergent payload on the same key is `idempotency_conflict`; a stale expected revision on a new key is `storage.ErrRevisionConflict` → `idempotency_conflict` on the wire. On success the cron scheduler is kicked.
- **Typed scheduler dispatch** (`internal/runtime/cron_scheduler.go`): `TriggerCron` and the due-job loop both switch on `job.Payload.Kind`; report rows dispatch to `startReportCron` which builds `StartReport{Period, WindowCompleted, OperationKey: "cron.report.<jobID>.<NextRunAtMs>", AsOfMs: NextRunAtMs}` under a workflow actor (`cron:<jobID>`). Manual trigger, loop fire, and post-crash re-fire of the same instant converge on one admission/Run via operation-key replay; `ErrWorkflowRecoveryRequired` propagates as a start failure instead of minting a new revision. `updateCron`/`deleteCron` in `internal/rpc/control.go` reject `CronPayloadKindReport` rows — report settings rows mutate only through `settings.write`.
- **Bounded catch-up** (`internal/runtime/report_admission.go`, `report_period.go`): admission enumerates calendar window IDs between the last completed generation and the fired window (`skippedWindowsBetween`, civil stepping through `addPeriod`/`windowID`, IANA timezone, daily/weekly `2006-01-02` / monthly `2006-01` layouts, bounded). The skipped list rides the committed run input (`reportRunInput.Skipped`) and projects to `ReportResult.SkippedWindows` + `GenerationProvenance.Skipped` — durable evidence, no fan-out: at most the latest missed completed period generates per restart.
- **Omission fence** (`internal/runtime/workflow_service.go`): `recoverWorkflowRun` returns `ErrWorkflowRecoveryRequired` when `revision.RootPurpose == TrustedStrategyReport` and `s.deps.Report == nil` — an omitted `vivy/reports` generation fences active report runs as recovery-required instead of letting a generic executor touch them. Schedule disable (cron `enabled=false`), report capability disable (module present but unbound), and UI omission (module absent from generation) are three distinct documented states: disabled rows keep settings durable and simply do not fire; disabled capability keeps committed runs recoverable; omitted module fences in-flight runs.
- **Minimal settings UI** (`plugins/vivy-notebook/ui/vivy-notebook/src/reports.tsx`): settings form on the existing R2 surface — enabled checkbox, timezone/section/provider/model/schedule inputs, expected-revision save through `writeSettings`; `idempotency_conflict` re-reads and surfaces a conflict notice without clobbering. EN/ZH catalog (10 new keys).
- **Tests** (`internal/runtime/report_schedule_test.go`, both `report_test.go`): settings write validation matrix (invalid tz, foreign/deleted section, unsupported payload kind, revision CAS, replay), typed dispatch single-Run convergence under double-fire and restart, manual-overlap busy, calendar/DST window identity, bounded skipped enumeration, crash-recovery matrix (receipt reconcile, fenced resume, omission → recovery_required), shutdown distinction; `TestReportSettingsCommitReceiptReplay` added as the missing dialect-parity test for `CommitReportSettings` on sqlite **and** real Postgres.
