# R2 — Report generation and provenance UI

## Delivered
- `ReportsClient` in `plugins/vivy-notebook/ui/vivy-notebook/src/api.ts`: sealed adapter for `vivy.reports.{generate,get,cancel,settings.read}` on module `vivy/reports`. Decodes the report outcome envelope (`result`, not `data`); maps transport -32004/-32601/unavailable to `capability_unavailable`; never sends scope/actor/origin — the ActionHost binds those server-side.
- `src/reports.tsx`: generation panel mounted in the existing entry detail header (no second page, no polling service, no local task ledger). Period (daily/weekly/monthly) + window (completed/current) selectors, generate/regenerate, cancel by Run ID, status badge. Progress is the authoritative run projection re-read by Run ID only — never a percentage or socket guess. Duplicate clicks suppressed while a run is active; a lost acknowledgement keeps the same operation_key so the retry replays admission; `busy` admissions surface without minting a second run; capability-absent generations hide the whole panel.
- Provenance/candidate/feedback honesty (Task 2): report entries render a provenance strip (series, window, IANA timezone, as-of, outcome mode + categorized reason) driven by the persisted `GenerationProvenance`; revisions distinguish `generated` from human edits (generated rows offer `View generated version` / `Use this version` through the existing N1 adopt action with expected-version CAS — a stale adoption surfaces the backend conflict); comments anchored to a generated revision are labeled `included`; no source-validation badge is placed on human-edited prose; EN/ZH catalog entries.
- Real-backend e2e `ui/e2e/notebook-reports.spec.ts` (3 tests, serial): full lifecycle generate→provenance→human edit→comment→regenerate→generated revisions; backend restart mid-interaction does not fabricate a `failed` status and the run survives/rejoins; controls vanish in a notebook-only generation (new `recipes/no-reports.vivy.yml` = default minus `vivy/reports`, packed as a third e2e binary).
- Backend fix found by the e2e probe: `reportcontract.ReportAdmission` had no JSON tags and emitted `RunID/Created/Rejoined/Busy` on the wire; tagged `run_id/created/rejoined/busy`. Internal source digest re-pinned `e20a31fd`, plugin module pin re-pinned (fixed-point iteration).
