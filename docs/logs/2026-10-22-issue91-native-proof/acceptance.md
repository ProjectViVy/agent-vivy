# Acceptance

An exact native node replay returns the durable original result without another effect. Changing its task or complete original descriptor conflicts under the same Run/node owner. A claimed unknown outcome stays claimed and is never automatically retried.

Approval retains the complete original graph and selected node/task, rejects another Run/node/checkpoint target or mismatched task, and resumes through the existing Service/Eino path. Checkpoint restart preserves sibling results and cancellation. Old owner format-1 records and requests missing the original descriptor require explicit recovery; historical checkpoint bytes remain unchanged.

Workflow and parent-reply operation identities preserve exact original caller fields. Distinct fields containing punctuation or NUL cannot collide through a delimiter. Oversized identities fail before runtime/mailbox admission, with no truncation or hashed fallback.

Final acceptance requires integrated candidate gates and independent D14 review. No release or offline converter is produced by this follow-up.
