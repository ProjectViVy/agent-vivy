# Acceptance

A repeated workflow operation with the same actual definition, authority, input and definition snapshot resolves to one durable workflow Run. Changed input under that identity conflicts. A reused commit ID returns the original event sequences only for equal actual semantic input; changed private input, answers, outputs, checkpoint or lifecycle event cannot borrow its receipt.

After restart, resume claim identity and exact answers come from private SQL state. Public events cannot supply missing answers. A completed child or uncertain effect remains fenced under the existing operation owner. Foreign ProgramID/HostBindingID calls fail before child effects. Workflow draft edits remain author-scoped and CAS-protected; publishing another artifact with the current draft ETag is rejected, and changed used implementations allocate a new immutable revision.

New workflow detail/event responses identify the admitted ProgramID and contain no business digest fields. Authorized node-result inspection reads the protected SQL output owner. Native checkpoints retain actual engine/compiler/catalog/serializer bindings.

Final acceptance still requires integrated runtime/RPC/UI/real PostgreSQL and scoped repository gates, a split-origin browser workflow smoke, independent review, and the separately delivered D14 offline conversion artifact. Historical schema1/2 rows lack new executable ProgramID bindings and cannot be automatically replayed.
