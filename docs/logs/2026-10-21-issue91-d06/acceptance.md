# Acceptance boundary

Use the existing Story index for the final D01/D06 status. This record describes
the observable contract and the evidence limits; verification.md records results.

A freshly packed Recipe has one opaque Generation ID in generated Go/UI, embedded
Manifest and nonexecuting Inspect. Independent packs receive different IDs.
Authoring generation with identical explicit inputs and authoring-default produces
no second-pass byte changes. Structural schema/version/framing errors, ambiguous
manifests, duplicate owners, T2 core impersonation and source/ref/root mismatches
are rejected. Omission, selected construction, lifecycle rollback and actual
Provider failure behavior remain effective.

All ten checked-in Recipes and official external-module/Go-host fixtures must
actually pack and inspect. Minimal boot alone is insufficient. Current Recipe
identities and inputs are recorded separately. Native Git/module/package/TLS
integrity remains enabled; conformance executes behavior and makes no source-
authenticity claim.

Fresh Studio/core stores require no Generation hash. Quiescent supported copies
convert without losing Generation/evaluation/promotion/release/installation/event
history or rollback assets. Unknown shapes and unlisted intermediate 036 core
stores refuse before runtime writes. Never open a converted target with an old
executable. Conversion failure leaves the source intact and permits explicit
retry; final upgrade packaging/publication remains D14.

D01's real App/provider/file-tool test proves exact tool result/call continuation,
final/terminal/idle behavior, absent digest audit and required Journal behavior.
Retained hooks/nudge/recovery and every historical failure have scoped dispositions.
The owner-selected wiring/kernel/affected Face/Web route is the acceptance gate;
full-product Windows/release CI and overall #91 closure remain separate.

Rollback source through the focused Git commits; preserve quiescent source-store
backups and cut back to them deliberately rather than discarding converted writes.
The compatible Studio commit is local-only because no push was authorized; publish
both repositories together before remote reuse of the new gitlink.
