# Acceptance — VC-2 automatic session titles

How a human can tell it worked.

## Product view (Web UI at http://127.0.0.1:3015, split dev pair)

1. Start the split pair (`just dev`) with a provider configured. Create a
   new session — the session list shows the localized "New session" placeholder
   in muted gray, not a stored fake title.
2. Send a first message and let the run finish. Within seconds the session
   in the drawer renames itself to a short label (3–6 words) generated by
   the model — small model first if `runtime.small_model` is configured,
   otherwise the main model.
3. Rename the session manually, then run another exchange in it: the title
   stays exactly what the user typed. The auto-titler never overwrites a
   user rename.
4. Clear `runtime.small_model` (or set it to a bogus model id) and repeat:
   sessions still get named — by the main model, or, if no model is
   reachable at all, by a plain truncation of the first user message
   (≤60 runes). A session is never left without some label after its first
   exchange unless every naming path failed, in which case it keeps the
   placeholder.
5. Channel, headless (`vivy run`), and cron sessions are never renamed —
   their titles are programmatic and non-empty from birth.

## Config view

`config.example.yaml` documents the knob:

```yaml
runtime:
  # small_model: gpt-4o-mini   # cheaper same-provider model for titles
```

Only the model id is pinned; base URL and key come from the active
provider (one data source, D9).

schema migration — stored empty titles are just empty strings, and a
