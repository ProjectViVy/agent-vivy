# Acceptance

While a turn is running, submit follow-ups with different thinking/mode preferences, an image, or captured file context. Queue state must show each full submitted snapshot; refreshing the page or reconstructing the service must retain it. After the active turn settles, the kernel must run compatible contiguous text batches and preserve differing options and multimedia/context submissions as successive FIFO admissions. User transcript attachments and context bytes must match the accepted snapshots.

A queue write failure must return an error without a visible or acknowledged memory-only item. A failed admission must leave no new run or driver and must retain the pending ordered queue. Concurrent queue reads must wait for complete replay. Removing a turn before its captured drain snapshot is admitted must prevent that text from running.

Steer twice across native tool/model boundaries in one run. Both steering turns must reach the same run, retain its thinking/identity context, and use the fresh boundary cancellation handle. If the checkpoint resume engine is unavailable, the accepted steer must remain intact and run as a follow-up. User abort must remove queued turns in the same durable transaction as the cancellation terminal; a failed parked cancellation can be retried.

Clear a queue with multiple items while injecting failure for a later removal: both live and replayed queue must remain unchanged. Successful dequeue/remove/clear returns complete turn DTOs, and abort events contain those DTOs. The dependent observer lane verifies editor restoration and resubmission of those snapshots in both faces; root verifies real split-server browser reload behavior.
