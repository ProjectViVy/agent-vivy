# Workflow inputs: author canonical `node.inputs`

Issue #81 / Epic E3 (L2 Workflow), story W1. Lane `feat/issue81-workflow`
(`.worktrees/issue81-workflow/agent-vivy`), based on `main` at `16808b5a`.

## Defect

The properties panel read and wrote the inputs map under `node.config.inputs`
(`plugins/vivy-workflow/ui/vivy-workflow/src/editor/NodePanel.tsx`). INOFY
resolves bindings from `Node.inputs` (tagged `inputs`; `types.go`, `bindInputs`
in `internal/einoruntime/workflow.go`), and
the host executor decodes `config` with `DisallowUnknownFields`. An authored
input map therefore either vanished (ignored) or rejected the node at
publish/run, while the panel's own roundtrip looked successful.

## Change

- New `plugins/vivy-workflow/ui/vivy-workflow/src/editor/node-inputs.ts`:
  `readNodeInputs`, `parseBindingMap` / `parseBindingMapValue`, `setNodeInputs`,
  `formatNodeInputs`. Top level must be an object; each value must be a
  non-null non-array object using only `literal` / `source` / `pointer`, with a
  non-empty string `source` and a string `pointer` (`""` is the whole-packet
  root pointer and is preserved). An empty map removes the field instead of
  persisting `{}`.
- `NodePanel.tsx` now reads `node.inputs`, commits through `setNodeInputs`,
  and refreshes the draft on `[node.id, node.inputs]` instead of
  `node.config`. `config` keeps only node-type fields (`task`, `tool_names`,
  timeout).
- `ui/vitest.config.ts`: the workflow Module's tests only ran from their
  generated staged copies (`ui/src/generated/ui/vivy-workflow/**`, matched by
  the blanket `src/**/*.test.*` include); the authoritative module sources
  were absent from the include list, so source drift could stay green behind a
  stale copy. The module source glob is now included and the staged copy
  excluded — the same split the masks/toolkits/persona/session-tree/notebook
  entries already use. `@xyflow/react` and its stylesheet resolve from the ui
  install, exactly like the staged build, because Module sources carry no
  local `node_modules`.
- `internal/runtime/workflow_product_inputs_test.go`: the runtime proof that
  all three binding kinds (literal, root `input`, upstream node output) survive
  draft → publish → admitted run, reach the dependent child task as labelled
  untrusted data, and that a later draft edit cannot move the published
  revision.
- Module identity: `plugins/vivy-workflow/vivy-module.yaml` and
  `plugins/vivy-workflow/module.go` now carry the recomputed tree digest
  `cc1b09e6…`; `ui/src/generated/assembly.ts` was regenerated by
  `sdk stage-ui` because it embeds that digest.
- Browser suite on isolated ports: `ui/playwright.workflow.config.ts`,
  `ui/e2e/workflow-setup.ts`, `ui/e2e/workflow-correctness.spec.ts`, plus an
  additive `hang` reply and address parameters in
  `ui/e2e/continuity-setup.ts`. `ui/.gitignore` covers `.workflow-e2e/`.

## Explicitly not done

- No backend, RPC, storage, admission, recipe, or schema change. The
  canonical home already existed; this removes the second, wrong home in the
  editor.
- No handling of legacy artifacts that already carry `config.inputs`: the
  backend rejects them (`json: unknown field "inputs"`), and the panel no
  longer produces them.
- Independent workflow launch from an idle session is unchanged here; it is
  the separate W2 delivery in the same lane.
- Shared status files (`docs/TODO.md`, `docs/DEFER.MD`) were not edited: the
  product-gaps plan package reserves them for one centralized writer, so the
  disposition is recorded in this log instead.
