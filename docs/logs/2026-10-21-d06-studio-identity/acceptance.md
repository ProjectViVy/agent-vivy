# Human acceptance

On disposable data, open a fresh Studio ledger, pack a Generation and verify
its opaque SDK identity and exact binary SourceRef appear in the ledger.
Evaluation runs the candidate itself; release still requires human confirmation
and an evaluation of that candidate. Install and rollback retain their lifecycle
records and actual body bytes.

Opening a legacy ledger must say `upgrade_required` without creating tables or
changing the source. Run the finite converter against a consistent disposable
source copy and a new target home with an existing parent. Verify Generation,
evaluation, release, installation and event history, custom-output artifact
mapping, snapshots, reopen and rollback before choosing the copied home.
Missing artifacts, unfamiliar formats and failed staging must leave the source
and configured home usable and must not publish a target.

In the Studio workbench current-species card, verify Generation, Binary,
protocol, policy profile, Recipe, Grants and Tools remain; retired hash rows are
absent. Release/install/rollback prompts retain explicit confirmation.

Acceptance of all D06 remains contingent on sequential shared-core format
integration, the final generated candidate checks, the shell's native/browser
acceptance and D14's separately retained finite transition artifact.
