# 2026-09-04 · Session Todo Status Mutation (Session Todo Mutation)

Date: 2026-09-04
Status: complete
Lane: `feat/ui-todo-mutate` worktree (`agent-vivy-ui-todo-mutate`)

## Outcome

Closed the UI todo-editing capability that had previously been explicitly marked as not to be implemented in `docs/logs/2026-08-29-chat-plan-todo-display`.
Through the authoritative control-plane RPC `session/todo/update` and the UI-side optimistic update + failure rollback mechanism, users can directly intervene during an idle session and update the status of session-scoped todos (complete, cancel, restore).

## Delivered

### 1. Backend control-plane RPC (`internal/rpc/control.go`)
- Registered and exposed `session/todo/update`, and added `session.todo.update` to the `capabilities` declaration.
- Accepts request parameters `session_id`, `id` (`todo_id` remains supported for compatibility), and `status`.
- **Status validation**: supports the four valid statuses `pending`, `in_progress`, `completed`, and `cancelled`.
- **Runtime guards**:
  - Session existence check (`CodeNotFound`).
  - Checks active runs (`deps.Runs.ListActiveRuns`); when the session exists with an unfinished run, returns `CodeConflict` ("session has an active run"), preventing concurrent write conflicts with model tool execution.
  - Single-in-progress mutual-exclusion constraint: when attempting to mark a task `in_progress`, checks whether the current session has another `in_progress` task and returns `InvalidParams` ("only one task may be in_progress") if so.
- Persists the update on success and returns the updated todo DTO.
- Test coverage: added `TestControlHandlerUpdatesTodo` in `internal/rpc/control_test.go`.

### 2. Frontend client and state flow (`ui/src/lib/`)
- `ui/src/lib/api.ts`: registered `session/todo/update` in `RPC_METHODS` and exported `updateTodo(sessionId, id, status)`.
- `ui/src/lib/store.ts`: added `updateTodoStatus(todoId, status)`:
  - Interception guard: if there is an active run (`runActive(currentRun)`), blocks the request without sending it.
  - Optimistic update: updates local state first and clears the error.
  - Failure rollback: if the RPC call fails, automatically restores the previous todo status and writes the error to `todosError`.
- Unit tests: added update, runtime interception, and failure rollback cases in `ui/src/lib/api.test.ts` and `ui/src/lib/store.test.ts`.

### 3. UI interaction and localization (`ui/src/components/planning/SessionTodoPanel.tsx`)
- Todo list item (`TodoRow`):
  - Replaced the status on the left with an interactive `Checkbox`: completed items are checked, and clicking toggles between `completed` and `pending`.
  - `in_progress` tasks remain adjustable when not disabled and show a loading animation while executing.
  - Right-side hover action button: shows the `Ban` icon for non-cancelled items (marks them `cancelled`) and the `RotateCcw` icon for cancelled items (restores them to `pending`).
  - Status synchronization: completed items use muted text, and cancelled items receive a strikethrough.
- Lock during runs and busy periods:
  - Shows a “Locked during execution” badge at the top of the panel (`todos.runningLocked`).
  - Automatically sets controls to `disabled` when `isRunning || runBusy`, preventing accidental user interaction.
- Localization (`ui/src/i18n/{zh.ts,en.ts}`): added bilingual prompt copy for completing, cancelling, and restoring todos, plus the runtime lock.
- Automated tests: added `ui/src/components/planning/SessionTodoPanel.test.tsx` (6 test cases).

### 4. Testing and platform stability
- `internal/codeface/launch_test.go`: added the `filepath.EvalSymlinks` handling needed on Windows and fixed absolute-path matching assertions.

## Explicitly not done

- Arbitrary addition or deletion of todo items (the authoritative todo structure and step planning are still generated by model task planning; this change only opens the human-intervention status loop).
- Cross-session todo modifications.
- Forced concurrent modifications that bypass the Run state machine.
