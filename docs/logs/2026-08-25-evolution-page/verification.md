## Browser smoke (split Vite, `http://127.0.0.1:3015/evolution`)

Reused the split pair already running locally (Vite 3015 + control plane 8787).
Verified each item in the in-app browser:

1. The sidebar “Evolution” is a real link (no “Not Implemented” badge), and
   `/evolution` renders the page header + DemoBanner.
2. All three Tab counts update live: Skill (0→1), Pending Review (1→0), AutoDream (3).
3. Pending Review details include the title/reason/status badge/base hash/full
   proposal/Evidence JSON.
4. **Accept loop**: click “Accept” → the button is disabled while busy → the
   request becomes “Accepted,” the Pending Review count reaches zero, and the
   Skill count increases by 1; the Skill tab shows the new authoritative skill
   `vivy-doc-sync`, its content hash updates, the authoritative Markdown is the
   full proposal, and an “Already processed” notice appears.
5. Skill details include Edit / Disable / Hard Delete / History Snapshots buttons.
6. AutoDream: 3 runs (2 completed, 1 failed with a reason); run-demo-1 details
   include trigger/mode/stage, start/end, attempt count, input summary + **5-event
   progress timeline** + “View Pending Review Request”.
7. Cross-tab navigation: “View Pending Review Request” → returns to the Pending
   Review tab and automatically selects the matching proposal details.
8. All state persists after refreshing (localStorage demo storage).

Two non-defect notes during the process:

- The old browser tab entered a degraded state later (clicks/screenshots failed
  and the event panel falsely reported empty); the event panel worked in a new
  tab. Other data-layer unit tests corroborated the result, so this was judged a
  host-tab issue rather than a product defect.
- The first-run wizard (WelcomeWizard, an existing feature) appeared after a
  reload; it is unrelated to this change and disappeared when skipped.
- Demo data is seeded only when its corresponding localStorage key is missing.
  A browser that visited the old Skills page may cache the old
  `vivy.demo.skills` (without evolution-managed items), leaving the Skill tab
  empty—clear that key or use a fresh environment to see the seed data (accepting
  any request also creates a new evolution-managed skill).
