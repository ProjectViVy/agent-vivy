# Acceptance

Use the complete examples under examples/ with a fresh disposable home. Minimal
Inspect selects exactly nine owners, including protected-tools and provider-
profiles, with no frontend assets. Its actual gateway performs a nonce read,
returns the exact durable result/call ID to request two, commits a final answer
and one terminal, then reports no active background Run.

The hello-fs example adds one explicit ToolWorld plus fs.read Grant, enables
hello_stat and binds its terminal Session to the seeded workspace using the
shared bootstrap. Its actual read reports the nonce file's length through the
same governed production path. The bootstrap prints the confirmed Session ID;
the existing terminal must select that Session, not create an unbound one.

minimal-chat Inspect selects the same nine owners plus PresentationHost and
vivy/minimal-chat. Open the split page at http://127.0.0.1:3015. Enter a workspace
before the first message and ask to list it and read nonce.txt. The browser
shows the real protected-tool output and final answer with Completed. Send is
disabled during an active Run; Cancel reaches its existing owner and produces
Cancelled. A deterministic provider error produces Failed and a visible error.
Each case has one committed terminal and returns idle. A narrow viewport keeps
the composer usable and the transcript independently scrollable.

Local deterministic proof uses the packed eleven-owner gateway and mock model;
it does not certify credentials or live-provider behavior. D14 must perform the
real-token human check, final full-product/native validation and finite upgrade
release integration. #91 remains open. Reverting D13 is a code/Recipe rollback;
no database schema or tenant data rollback is introduced here.
