## Smallest missing cross-boundary scenarios

1. **Three-fold Chinese continuity chain (core path can be prepared before S5).** Use one visible main binding; A and B may be distinct authorized internal segments. Drive actual Service/tool/Journal evidence, not only seeded assistant text. A contains a dated decision, later correction, explicit promise, unfinished action and independently scripted tool-verified result. Force three successful contiguous native folds, then normal App restart and B. Record each actual summary/foreground request and digest, exact positive operation receipt, base/revision/epoch/range, run/source pin and every original source digest. Check previous head appears exactly, only new prefix is folded, latest whole suffix/current appear once, exact tool fields survive and all original bytes remain readable after every cut. A scripted fixture proves transport/state preservation; real semantic quality belongs to S6 Task2.
2. **One zero-new supersession lifecycle chain (core path can be prepared before S5).** Cover A, archive authorized A, apply rewind/admission-edit, and initiate current B with no newly completed interaction. Explicit compact must reconcile equal range/epoch; unchanged repeat performs no model/commit work. Reopen the same host/owner, restore pre-correction text, require fresh reconciliation before B HTTP, then clear both during an in-flight summary and after positive commit. Assert withdrawn stale text never reappears, no covered-original refold/fake interaction, exact canonical/view refs, unchanged originals and truthful first-request/next-leg timing. Reuse the existing clear/resume and copied-view leaves rather than duplicating their entire tables.
3. **Receipt-before-use plus true three-way CAS (core path can be prepared before S5).** Add deterministic barriers around actual summary response, C1 commit/lookup and foreground send. Withhold/return unknown after an attempted commit: no provider B request and no retirement may follow visible head/digest alone. Release an exact positive operation receipt, then prove fresh recapture and complete B input; cancellation or recapture failure must preserve originals and pause. Separately release two overlapping summaries around one human edit/clear to prove both stale candidates cannot overwrite it and recomputation remains bounded. Reuse existing errors/cuts as evidence rows; this scenario supplies the missing simultaneous causal order.
4. **Duplicate terminal→one projection with failed/retried delivery (requires accepted S5).** Through normal selected composition, persist exact source first, deliver the same terminal repeatedly/across restart, inject projection failure and retry, and assert one seal plus one deterministic native operation receipt. Attempt a composition where both BML and cognitive legacy sinks claim LIFE; require rejection/exclusion, not two writes. Observe actual receipts and retained retry cursor, not a fake receiver counter alone.
5. **Index lag/tombstone→authorized exact source navigation (requires accepted S4 source action + S5).** After a real fold/projection, delay the selected BML index or tombstone its record; resolve exact original attachment/tool references through C4→authorized C2, compare bytes/digests and demonstrate Recap/admission continuity. Revoke/change a source grant and require refusal; missing original must be unavailable, with no summary fallback or claim that deleting a backend record erased core/Recap.
6. **Selected-composition security/legacy closure (requires accepted S5; consume accepted S4 actions where used).** Run ordinary Coding after LIFE with execution/compaction unchanged; LIFE coding tool execution still governed; no reflection/evolution dependency; WORLD/worker/private/foreign/deferred-tool paths receive only their allowed context. Feed old pending capture/Work/FoldSession deliveries into v3: no mutation, explicit policy-skipped receipt, no infinite retry; preserve readable committed old receipt/nonempty v1/v2 bytes. Reuse fixed pin/path/owner tests as prerequisites, then check normal selected composition cannot bypass them with a second directory/Store. Do not create a parallel owner just to make the test pass.
