`ui-tool/` = `packages/client/ui-tool/`, `primitives/` = `packages/client/ui-primitives/`, `web/` = `apps/web/`.

## File mutation / diff

- Dispatch: `ToolCallTree` sends every atomic call through the keyed slot `tool.call.toolview` with `entryKey: toolName` and `fallback: <GenericToolCard/>` (`ui-tool/src/client/tool/ToolCallTree.tsx:46-49`).
- One component, two keys: `FileMutationRow` is registered under `edit` **and** `write` (`ui-tool/src/client/tool/toolviews/file-mutation-row.tsx:43-44`), icon `<IconEditOutline16 size={14} />` (`file-mutation-row.tsx:23`), title `t(model.titleKey)` → `tool.title.edit` = "Edit" / `tool.title.write` = "Write" (`locales.ts:262,261`).
- The diff itself is drawn by the primitive `DiffBlock` (`primitives/src/DiffBlock.tsx:173`), rendered by `ToolRow` as its card body with `maxLines={CHAT_DIFF_MAX_LINES}` (`ui-tool/src/client/tool/components/ToolRow.tsx:251`).
- Path header: `DiffBlock` emits one `kind:'path'` row per new file, verbatim from the hunk's `path` (`primitives/src/DiffBlock.tsx:114`); repeated same-file hunks get a `⋯` gap row instead (`DiffBlock.tsx:115-118`).
- Counts: collapsed row carries `+{added} -{removed}` computed by `diffTotals` (`ToolRow.tsx:170-174`), rendered in a non-shrinking suffix span (`ToolRow.tsx:232-234`); the expanded footer is `└ +{added} -{removed} · {labels.files(files)}` (`DiffBlock.tsx:222`), e.g. golden `+1 -1 · 1 file` (`snapshots/web/diff-context/ui.expected.md:7`) and `└ +130 -130 · 1 file` (`snapshots/web/diff-bounded/ui.expected.md:9`).
- Unified, not split: rows are a flat list of kinds `path | del | add | context | gap` (`DiffBlock.tsx:47-50`); deletions/additions are marked with `- `/`+ ` drawn in CSS `content` (`primitives/src/DiffBlock.module.css:61-77`), so the sign reads without colour.
- Context lines: 3 on each side, from `structuredPatch(..., { context: 3, maxEditLength: 256 })` (`DiffBlock.tsx:75-77`); the host producer uses the same three (`packages/fs/tool-fs/src/diff.ts:11,34` `DIFF_CONTEXT = 3`). Golden shows a shared context line surviving: `mode=DEBUG + mode=RELEASE level=info` (`snapshots/web/diff-context/ui.expected.md:7`).
- Large / bounded diff: `computeHunkDiffs` gives the same approach; above the edit limit the primitive falls back to a whole-fragment replacement (`DiffBlock.tsx:76-77`), producing the bounded golden `large.txt … +130 -130` plus `Expand 252 more diff lines` → `… 252 more lines` (`snapshots/web/diff-bounded/ui.expected.md:1,8`).
- Collapse: a chat diff card keeps `CHAT_DIFF_MAX_LINES = 9` — "a file header, one removed/added pair, and three context lines on either side" (`ui-tool/src/client/tool/models/diff-card-model.ts:6-7`), i.e. tighter than the primitive default `DEFAULT_DIFF_MAX_LINES = 16` (`DiffBlock.tsx:9`). The cap is one head/tail fold per card (`DiffBlock.tsx:191-198`), **not** per-hunk; per-hunk there is only the `⋯` separator.
- Create: `write`'s host projection emits `diffs: []` when `value.before === null` (`packages/fs/tool-fs/src/write.ts:98-103`), so the client falls back to the argument-derived whole-file diff `{ path, oldText: null, newText: content }` (`diff-card-model.ts:70-74,106-113`); the golden for a create is an added-only card `+1 -0` (`ui-tool/tests/diff-card.client.spec.tsx:242-252`).
- Delete: there is no first-party delete tool in `packages/fs/tool-fs/src/` (only `write`/`edit`/`read`/`read_image`), so a removal surfaces as a write/edit whose `after` is empty: `contentLines('')` is zero lines (`DiffBlock.tsx:142-146`), i.e. an all-removed `-0` card. File removal through the shell goes to the bash family instead.
- Open/reveal: the collapsed summary is a path button when the row has `filePath` and `onOpenFile` (`ToolRow.tsx:179-185,216-224`), using `openFile(path, { line: filePathLine })`; `OpenFileOptions.line` is "1-based line to reveal" (`packages/client/ui-chat/src/client/contract/slots.ts:34-37`) and the chat wiring opens it in the right Sidebar under `dsh-resource://file/session/<id>/<path>` with `{ params: { line } }` (`packages/client/ui-chat/src/client/apply.ts:133-138`) — not a desktop app, despite `ToolRow`'s "opens the host default app" comment (`ToolRow.tsx:74-78`).
- Failure: an errored mutation derives no diff card (`diff-card-model.ts:106`); the collapsed summary becomes the error's first line and the expanded body is the raw IN/OUT text (`ToolRow.tsx:165,299-318`), e.g. `old_string not found in notes/demo.txt` (`ui-tool/tests/diff-card.client.spec.tsx:271-278`).
- `str_replace_editor` is only carded while running, for `create`/`str_replace` (`diff-card-model.ts:47-65,105`); it settles through Generic.
- Fields read: `call.argsRaw` → `file_path`, `content`, `old_string`, `new_string`, `replace_all` (`diff-card-model.ts:67-80`); `block.meta.diffs[].{path, oldText, newText}` (`diff-card-model.ts:28-40`); `block.isError`, `block.error.code`, `block.parentCallId`, result `content` text.

## Reads

- `ReadRow` (`ui-tool/src/client/tool/toolviews/read-row.tsx:14-20`) composes the shared read-family assembly `readFamilyRow` (`toolviews/read-family-row.tsx:37-59`) with `readCardModel` and `readCallLine`; icon `<IconBrowseOutline16 size={14} />`, `bodyRaw={null}` — "the path link is the only args interaction" (`read-family-row.tsx:5-6,50`).
- Title: `tool.title.read` = "Read" (`locales.ts:259`); summary is the args path (`tool-call-model.ts:171,188-189`), e.g. `src/a.ts`, and is the openable link landing on the read's `offset` line (`read-row.tsx:18`, test `ui-tool/tests/read-card.client.spec.tsx:244-251`).
- Card: primitive `ReadBlock` (`primitives/src/ReadBlock.tsx:67`), rendered with `maxLines={CHAT_READ_MAX_LINES}` (`ToolRow.tsx:253`), where `CHAT_READ_MAX_LINES = 8` — "half the primitive's own default" (`read-card-model.ts:17`; primitive default `DEFAULT_READ_MAX_LINES = 16`, `ReadBlock.tsx:19`).
- Banner: label (the shortened path), `read.window` = "Showing {shown} of {total} lines" (`locales.ts:283`; e.g. `显示 3 / 180 行`, `read-card.client.spec.tsx:237`), the language id, and `copy`/`copied` (`ReadBlock.tsx:124-137`). The window note appears only when `lines.length < totalLines` (`ReadBlock.tsx:107-109`).
- Line gutter keeps real file line numbers (`ReadBlock.tsx:112-116`), e.g. line `41`.
- Syntax highlighting: `lang` is an optional grammar hint carried through the card (`read-card-model.ts:31,70`, produced by `langFromPath(value.path)` at `packages/fs/tool-fs/src/read.ts:125`), highlighted via shiki with viewport-limited work and lazy grammar re-render (`ReadBlock.tsx:77-88`); absent/unknown lang = plain monospace.
- Truncation: two independent mechanisms — the card's head/tail fold (`ReadBlock.tsx:103-106,141-150`) with `read.expandRest` = "… {count} more lines" (`locales.ts:286`), and the host's byte cap signalled in the read envelope, not in the card (`packages/fs/tool-fs/src/read.ts:110-118`).
- Image reads: separate keyed row `read_image` → `ReadImageRow` (`toolviews/read-image-row.tsx:52-59`), classified into the read family so it keeps the browse icon and openable path (`tool-call-model.ts:53-57`), title `tool.title.readImage` = "Read image" (`locales.ts:270`). Body = in-card label, the gallery dispatched through the row-declared child slot `tool.call.images` (`read-image-row.tsx:58`, `ToolRow.tsx:266-270`), then the result's own envelope text (`ToolRow.tsx:264-272`), e.g. `image/png image, 1496x260 px` (`ui-tool/tests/image-card.client.spec.tsx:325`). The raw attachment object is never printed (`image-card-model.ts:20-28`), and a deployment without the image plugin still shows the text line (`image-card.client.spec.tsx:328-337`).
- Collapsed by default: every card. `open = expanded && expandable` with `useState(false)` (`ToolRow.tsx:137,157-158`); tests assert "the diff card is collapsed by default — not in the DOM until expanded" (`diff-card.client.spec.tsx:223-227`). Result-side cards only exist once settled: running reads/`read_image` show the summary row alone (`read-card-model.ts:105`, `image-card-model.ts:214`).
- Fields read: call args `file_path`, `offset`, `limit` (`read-card-model.ts:42-45`); `meta.{path,offset,lines[{number,text}],totalLines,lang}` (`read-card-model.ts:51-71`); result text must match `/^<path>…<\/path>\n<type>file<\/type>\n<content>\n([\s\S]*)\n<\/content>$/u` (`read-card-model.ts:111`). Image: `meta.path`, content blocks `[{type:'text'}, {type:'image', attachment:{attachmentId,mediaType,bytes,width,height,name?,originalDimensions?}}]` and the `<type>image</type>` envelope (`image-card-model.ts:61,113-150,236-240`).

## Search

- One component, two keys: `SearchRow` registered under `grep` and `glob` (`ui-tool/src/client/tool/toolviews/search-row.tsx:48-49`), icon `<IconSearchOutline16 size={14} />`, titles `tool.title.grep` / `tool.title.glob` — both literal "Grep"/"Glob", i.e. untranslated product words (`search-row.tsx:13-14,27-29`; `locales.ts:271-272`).
- The fallback path matters too: `GenericToolCard` derives the same search card, so an unregistered caller still gets it (`toolviews/GenericToolCard.tsx:39`).
- Card: primitive `SearchBlock` (`primitives/src/SearchBlock.tsx:177`) with two `kind`-discriminated shapes: `matches` (grep, grouped per file) and `paths` (glob, flat list) (`SearchBlock.tsx:62-77`).
- Grouping/counting: a `file` header row carries the path and that file's match count (`SearchBlock.tsx:143-155,230-240`); the header summary is `search.matches` = "{shown} matches · {files} files" or `search.paths` = "{shown} paths" (`locales.ts:289,287`), e.g. visible rows `12: const foo = 1` under `a.ts` (`ui-tool/tests/search-card.client.spec.tsx:192-193`).
- Bounding: `CHAT_SEARCH_MAX_LINES = 8` in the chat row (`ui-tool/src/client/tool/models/search-card-model.ts:12`; primitive default 16, `SearchBlock.tsx:12`), applied as one head/tail fold over flattened rows — a file header costs one row exactly like a match (`SearchBlock.tsx:79-89,200-218`), and a tail slice restores its owning file header so rows stay attributable (`SearchBlock.tsx:207-218`).
- Truncation signal: `meta.truncated` + `meta.total` produce `search.matches.truncated` = "Showing {shown} of {total} matches · {files} files" / `search.paths.truncated` (`locales.ts:290,288`) — "the card never presents a capped result as complete" (`SearchBlock.tsx:34-40`). A capped result also prints the raw result text under the card as a recovery locator (`ui-tool/src/client/tool/components/ToolRow.tsx:285-287`), e.g. `(Full grep result stored at: spill://grep-1 …)` (`search-card.client.spec.tsx:310`).
- Per-file expand: yes — each file header is `<button aria-expanded={!row.collapsed}>` toggling that group's match rows (`SearchBlock.tsx:230-240,191-198`). There is no per-path expand for glob.
- Empty and copy: `search.noResults` = "No results" (`locales.ts:291`, `SearchBlock.tsx:254`); copy writes the whole structured result regardless of folding (`SearchBlock.tsx:98-103`).
- Fields read: args `pattern`, `path`, and grep `include` (rejecting empty, `!`-prefixed, or top-level-comma forms) (`search-card-model.ts:22-47`); `meta.shape` (`'matches'|'paths'`), `meta.truncated`, `meta.total`, `meta.files[].{path,matches[{lineNumber,line}]}` or `meta.paths[]` (`search-card-model.ts:49-99`); raw result text only for the recovery locator (`search-card-model.ts:91`).

## Shell / terminal / background jobs

- Note on provenance: the bash row lives in a file named `bash-sample.tsx` but is the production registration — `apply.ts` plugs `bashToolviewSample` and it registers key `bash` (`ui-tool/src/client/tool/toolviews/bash-sample.tsx:156-162`, `ui-tool/src/client/apply.ts:43`). The README calls this "the built-in shell/pwsh … presentations" (`ui-tool/README.md:46`). `pwsh` has **no** keyed row and lands on `GenericToolCard`, which derives the same terminal card (`tool-call-model.ts:51`, `toolviews/GenericToolCard.tsx:36`).
- Card: primitive `TerminalBlock` (`primitives/src/TerminalBlock.tsx:146`), fed by `terminalCardModel` (`ui-tool/src/client/tool/models/terminal-card-model.ts:283`) and localized by `localizeTerminalCardModel` (`terminal-card-model.ts:66`).
- Prompt line(s): cwd label + command, one row per command line (`TerminalBlock.tsx:186-221`); cwd is the call's workdir resolved against the session workspace, `.`/`..` collapsed, bare `$` on later rows (`terminal-card-model.ts:108-112`, `TerminalBlock.tsx:216-218`); golden `Failed {{workspace}} Get-Item missing.txt exit code 1` (`snapshots/web/pwsh-terminal/terminal-card.expected.md:1`).
- Streaming output: none in the transcript. While running, `terminalCardModel` returns `running: true, output: undefined` — "the block shows the prompt line alone" (`terminal-card-model.ts:296-306`, `TerminalBlock.tsx:57`); output renders only once the result node settles (`terminal-card-model.ts:309-311`).
- Exit code / signal: parsed from the result's trailing markers — `/\[exit code: (\d+)\]$/` and `/\[killed by signal: ([^\]\n]+)\]$/` (`terminal-card-model.ts:265-271`), removed from the display text (`terminal-card-model.ts:311`). Status pill text is `terminal.exitCode` = "exit code {code}" or `terminal.signal` = "signal {signal}" (`locales.ts:315,314`); a clean exit shows no pill (`TerminalBlock.tsx:92-100`). A failing exit is surfaced as the collapsed row's red state even though the call settles `isError:false` (`terminal-card-model.ts:86-97`, `GenericToolCard.tsx:43-45`, test `ui-tool/tests/terminal-card.client.spec.tsx:449-454`).
- Run-state dot: one per card, on the first prompt row, `ongoing | done | error` with labels `terminal.running` / `terminal.done` / `terminal.failed` (`TerminalBlock.tsx:118-127,209`); the row and its card must agree (`terminal-card.client.spec.tsx:437-447`).
- Truncation: in chat rows the command output is **not** head/tail-folded — the chat sites pass `maxLines={Infinity}` and the card scrolls inside its own 224px output area (`ToolRow.tsx:245`, `bash-sample.tsx:115-117`, `ToolRow.module.css:337-345`), which is what "the scroll container replaces the middle collapse" asserts (`terminal-card.client.spec.tsx:316-325`). The 16-line head/tail fold (`terminal.expandAria` / `terminal.expandRest`, `locales.ts:321-322`) is the primitive default used by other surfaces.
- Empty output: `terminal.noOutput` = "No output" (`locales.ts:319`, `TerminalBlock.tsx:230-231`). `terminal_send` copy falls back to `terminal.sendInput` = "(send input)" and description `terminal.session` = "Terminal {sessionId}" (`terminal-card-model.ts:76-82`, `locales.ts:325-326`).
- Abort/kill: an interrupted call becomes state `stopped` (`tool-call-model.ts:241-243`: `block.error?.code === 'interrupted'`), the leading icon is replaced by an amber `StateDot state="warning"` (`ToolRow.tsx:90-96`, `bash-sample.tsx:26`), with hidden AT text `row.stopped` = "Stopped" / `bash.stopped` (`ToolRow.tsx:102-109`, `bash-sample.tsx:33-40`). The aborted bash row expands to the raw IN/OUT body (`bash-sample.tsx:59-61`), golden `Failed Bash Error: tool call aborted` + `IN { "command": … } OUT Error: tool call aborted` (`snapshots/web/bash-abort-row/ui.expected.md:22-26`, `web/tests/bash-abort-row.e2e.ts:58-67`).
- Background: `terminalCardModel` returns null for a `run_in_background: true` call (`terminal-card-model.ts:205,255,290`), and the bash row deliberately leaves such acknowledgements collapsed — "background acknowledgements and malformed calls remain collapsed" (`bash-sample.tsx:57-61`; test `terminal-card.client.spec.tsx:496-504`). Jobs are not shown in the transcript at all: the session header renders a `JobListAction` popover only when jobs exist, with kind, label, status word and a ticking duration over statuses `running|stopping|completed|killed|failed` (`packages/client/ui-jobs/src/client/JobListAction.tsx:44-54,120,155-177`), golden `- list "Background jobs": - listitem: bash sleep 45 running {{duration}}` (`snapshots/web/background-job-list/running.expected.md:1-2`).
- Spill: output carrying a spill notice must not establish success — the call stays on the generic IN/OUT path instead of a terminal card (`terminal-card-model.ts:226-236`, `bash-sample.tsx:59-61`).
- Persistent shells (`bash`/`pwsh` without `description`): terminal card while running, generic input/output once settled, and expandable at root (`terminal-card-model.ts:192-206,216-221`, `ui-tool/README.md:46`; test `terminal-card.client.spec.tsx:464-482`).
- Fields read: args `command`, `description`, `workdir`, `timeoutMs`, `run_in_background`, `sandbox_permissions`+`justification`; `terminal_send`'s `sessionId`, `text`, `submit` (`terminal-card-model.ts:184-207,245-257`); result single text block for output+status (`terminal-card-model.ts:309-311`).

## Cross-family conventions

- One dispatch rule: atomic views are keyed by wire tool name; unregistered names (and Auto-review denials) use `GenericToolCard` (`ToolCallTree.tsx:34-49`). Every root and nested PTC child wrapper keeps `data-chat-anchor-key="call:<id>"` and `data-chat-call-id` (`ToolCallTree.tsx:41-42`); children recurse through the same path (`ToolCallTree.tsx:74-90`).
- Row chrome: one 24px `DisclosureRow` — `[16 leading] title [2px dot separator] summary (ellipsized FILL)`, whole row is the toggle and the collapsed summary stays visible while open (`ToolRow.tsx:199-236`, `primitives/src/DisclosureRow.tsx:72-102`, `ToolRow.module.css:1-7`).
- State is one enum for every family: `running | ok | error | stopped` (`tool-call-model.ts:21`), driven by settlement (`tool-call-model.ts:241-243`); `error`/`stopped` swap the icon for `StateDot state="error"|"warning"` (`ToolRow.tsx:90-96`), and `running` keeps the icon and adds a CSS glare sweep (`ToolRow.module.css:19-43`). Colour-only signals are duplicated as visually hidden text (`row.running`/`row.failed`/`row.stopped`, `ToolRow.tsx:102-109,198`).
- A failure replaces the summary rather than supplementing it, and the error's first line is the collapsed text (`ToolRow.tsx:164-166,257`).
- Every card is collapsed by default and mutually exclusive: `const card = askQuestionBody ?? terminalBody ?? diffBody ?? readBody ?? imageBody ?? searchBody ?? webBody` (`ToolRow.tsx:156`).
- Fallback order after the card: the code variant's program through `CodeBlock`, otherwise an IN/OUT card with `row.input`/`row.output` and a hairline divider (`ToolRow.tsx:193-196,299-318`).
- The Inspect pill is hover/focus revealed under the expanded body and is the only route to the trajectory view (`ToolRow.tsx:322-331`, `ToolRow.module.css:164-192`).
- Result cards are result-side only: running calls show the summary row alone across diff/read/image/search/web (`diff-card-model.ts:104`, `read-card-model.ts:105`, `image-card-model.ts:214`, `search-card-model.ts:83`, `web-card-model.ts:59`).
