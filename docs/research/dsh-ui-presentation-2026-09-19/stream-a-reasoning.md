## Behaviour

1. **Where reasoning appears.** Reasoning is not its own transcript node: it is an `AssistantBlock` of kind `reasoning` inside the `assistant-step` node, and `AssistantMarkdown` renders each one as a `ReasoningRow` —
   `case 'reasoning': rendered.push(<ProcessReasoning …><ReasoningRow text={block.text} running={streaming && i === last} t={t} /></ProcessReasoning>,)` (`AssistantMarkdown.tsx:85-95`).
   The row is therefore per-block: several reasoning blocks produce several rows, keyed by block index (`AssistantMarkdown.tsx:86`). The node kind is registered once — `{ name: 'conversation.chat.node', key: 'assistant-step', locale: NS }, AssistantNodeView` (`register-node-renderers.ts:26-27`).
   Visually it is its own collapsible row, not part of the assistant prose: `DisclosureRow` supplies "[16px leading] gap 6 [title 13/24]" (`DisclosureRow.module.css:1-2`) and the body renders under it (`ReasoningRow.module.css:107-115`).
   **Default state is collapsed, always**: `const [expanded, setExpanded] = useState(false)` (`ReasoningRow.tsx:29`), and the doc comment says "*Render one assistant reasoning block collapsed until the reader opens it*" (`ReasoningRow.tsx:20-22`).
   Streaming vs finished changes only the summary source and the state attribute: `data-state={running ? 'running' : 'ok'}` (`ReasoningRow.tsx:36`), with `running` true only while `streaming && i === last` (`AssistantMarkdown.tsx:92`). A *completed* row is still collapsed — nothing auto-expands on settle (pinned at `reasoning-row.client.spec.tsx:65-77`). There is **no error state on the reasoning row**: `data-state` only ever takes `running`/`ok`; an aborted assistant instead gains the `.stopped` chip inside the body (`AssistantMarkdown.tsx:138`, `AssistantMarkdown.module.css:55-63`).
   Separately, reasoning can be *hidden wholesale* by the turn-level fold: `reasoningHidden = turnProcess.foldable && turnProcess.spec.answerStep === data.step && turnProcess.spec.inlineReasoning && !turnProcess.open` (`AssistantNodeView.tsx:23-27`), applied through `ProcessReasoning`, which sets `data-turn-process-inline` and relies on `hidden="until-found"` (`AssistantMarkdown.tsx:144-151`, `searchable-hidden.ts:21`).

2. **Exact labels and indicators.** Collapsed title is `t('message.think')` (`ReasoningRow.tsx:46`) → `'message.think': 'Think'` / `'思考'` (`ui-chat/src/client/locale.ts:170`, `:59`). Summary text is data, not copy: `(running ? latestLine(text) : firstLine(text)).replaceAll('**', '')` (`ReasoningRow.tsx:30`) — last line while streaming, first line when settled, double-asterisk markers stripped.
   Running indicator: a screen-reader-only `{running && <span className={a11yCss.visuallyHidden}>{t('row.running')}</span>}` (`ReasoningRow.tsx:39`; `ui-chat/src/client/chat/accessibility.module.css:1-8`) → `'row.running': 'Running'` / `'运行中'` (`ui-conversation/src/client/locales.ts:252`, `:92`), plus a visual CSS sweep (`ReasoningRow.module.css:32-46`).
   Turn-process controller labels: `'message.turnProcess.toolCalls.one'` / `.other` / `.messages.*` / `.subagents.*`, joined with `t('message.turnProcess.separator')` = `' · '`, with fallback `t('message.turnProcess.thoughtForAWhile')` = `'Thought for a while'` / `'已思考'` when every count is zero (`TurnProcessNodeView.tsx:13-40`; `locale.ts:173-180`, `:62-69`).
   **No elapsed time and no token count is shown on the reasoning row.** Elapsed time is turn-scoped: `TurnStatus` renders `t('chat.deepDiving')` and only adds `formatRunDuration(elapsedMs, t)` once `elapsedMs >= 15_000` (`ChatView.tsx:188-198`; labels `locale.ts:136`, `:25`). Token/time figures live in the completed-turn tail (`message.turnUsage.*`, `message.ranFor`, `message.tokensPerSecond`) via `TurnUsagePanel`/`TurnTimePanel` (`TurnTailNodeView.tsx:52-64`; `locale.ts:84-99`, `:195-196`).

3. **Streaming turn structure.** Nodes are registered under one keyed seat: `user`, `steering`, `context`, `system-prompt`, `assistant-step`, `command`, `manual-compaction`, `compaction`, `model-retry`, `turn-error`, `turn-max-tokens`, `turn-process`, `turn-tail`, `unknown` (`register-node-renderers.ts:18-56`). The process *group* is a synthetic controller node inserted before the turn's process rows:
   `'turn-process', data.controlAnchorSeq + CHAT_SYNTHETIC_SEQ_OFFSETS.processControl` (`conversation-nodes/turn-process.ts:294-299`).
   `TurnProcessSpec` carries `processStartSeq`, `answerAnchorSeq`, `answerStep`, `inlineReasoning`, `messageCount`, `toolCallCount`, `subagentCount` (`contract/turn-process.ts:4-18`). The spec is fixed at the *latest* reply-bearing assistant step without tool calls (`conversation-nodes/turn-process.ts:117-122`), so everything between `processStartSeq` and `answerAnchorSeq` — reasoning, tool calls, injected context — is "process", and the answer is what follows (`conversation-nodes/turn-process.ts:158-167`).
   Ordering is explicit: `presentationPosition` gives the controller rank `-1` when there is no opening human anchor (`chat-snapshot-builder.ts:381-389`) and rank `2` to nodes before the opening human input (`:376-380`); `orderedVisibleChatNodes` sorts by anchor then rank (`:400-413`).
   Per-node eligibility lives in `ChatNodeSeat`: `processWindowReady` needs compact mode, a **closed** turn, and complete history (`ChatNodeSeat.tsx:62-68`); `processMember` is `anchorSeq >= processStartSeq && anchorSeq < answerAnchorSeq` (`:69-73`); `processAnswer` is the assistant node on `answerStep` (`:74-77`); `foldable` needs a member, or a member-owning disclosure with `hasExternalProcess || inlineReasoning` (`:79-81`).
   **While the turn streams**, `turnClosed` is false, so `foldable` is false and the controller renders nothing — `if (!turnProcess.foldable) return null` (`TurnProcessNodeView.tsx:11`) — and every row (Think rows, tool rows) is visible in flow order.
   **When the turn closes**, the controller appears and the process rows collapse: `const processHidden = controllerInactive || (foldable && processMember && !processOpen)` (`ChatNodeSeat.tsx:98`) drives `hidden="until-found"` (`searchable-hidden.ts:21`), and the answer row tightens to an 8px gap: `.flowItem[data-turn-process-answer] { --dsh-chat-flow-gap: 8px; }` (`ChatView.module.css:60-64`). Expansion state is stored per turn+step (`ChatNodeSeat.tsx:48-60`; `stores.ts:24-43`).
   **Aborted / errored**: `turn-error` and `turn-max-tokens` are in `TURN_PROCESS_INDEPENDENT_KINDS` (`contract/turn-process.ts:20-33`) so they never fold into the process group; they render as their own status rows with a `StateDot` (`MessageItem.tsx:129-154`). An interrupted assistant keeps `status: 'interrupted'` (`AssistantNodeView.tsx:33`) and shows the stopped chip (`AssistantMarkdown.tsx:138`). *Inference from code, not test-pinned*: on a turn that ends with no reply-bearing answer, `answerStep` stays `null` (`conversation-nodes/turn-process.ts:137-147`), so `processAnswer` is false and the `anchorSeq < answerAnchorSeq` test is false — nothing folds and the controller stays inert.
   The turn ends with a tail row that also carries the finalized answer's actions, usage, and run time; `data-actions-reveal` is `'always'` for the latest turn and `'hover'` otherwise (`TurnTailNodeView.tsx:41`, `:44-66`).

## Visual and interaction contract

- Root: `display:flex; flex-direction:column`; collapsed (`not([data-expanded])`) is a fixed box — `contain: size layout; height: calc(24px + var(--dsh-content-font-delta, 0px))` (`ReasoningRow.module.css:1-9`).
- State hooks an implementer must reproduce: `data-variant="think"`, `data-state="running|ok"`, `data-expanded` (`ReasoningRow.tsx:33-38`).
- Row chrome from `DisclosureRow`: 24px row, `width: calc(16px + var(--dsh-content-font-delta, 0px))` leading box, `margin-right: 6px`, title `13px/24` (`DisclosureRow.module.css:16-23`, `:29-42`, `:79-84`); `cursor:pointer` when expandable (`:25-27`).
- Hover/focus affordance: the leading glyph fades out and a chevron fades in, `transition: opacity 100ms ease` (`DisclosureRow.module.css:57-77`). `Row:not([data-expanded])` shrinks the whole row to a 24px line.
- Collapsed summary: `.separator` is a `2px × 2px` dot, `border-radius: 1px`, `background: var(--dsw-alias-label-caption)`, `margin: 0 8px` (`ReasoningRow.module.css:65-72`); `.summary` uses `color: var(--dsw-alias-label-tertiary)`, `var(--dsh-content-font-size-secondary, 13px)`, `line-height: calc(20px + var(--dsh-content-font-delta-secondary, 0px))`, `white-space: nowrap` + ellipsis (`:77-91`). While running it flips to `justify-content: flex-end` and lets the text overflow (`width: max-content; min-width: 100%; overflow: visible; text-overflow: clip`) so the newest tokens stay visible (`:93-105`).
- Expanded body: `.thinkBody { padding: 4px 0 4px calc(22px + var(--dsh-content-font-delta, 0px)); color: var(--dsw-alias-label-tertiary); font-size: var(--dsh-content-font-size-secondary, 13px); line-height: calc(20px + …secondary…); white-space: pre-wrap; word-break: break-word; }` (`ReasoningRow.module.css:107-115`). ## Edge cases pinned by tests

- Collapsed by default, and manual expansion survives a new sibling block and the stream settling (`reasoning-row.client.spec.tsx:17-38`).
- Running summary tracks the newest line and keeps `data-follow-end="true"`; on settle the summary reverts to the first line and `data-follow-end` is removed (`reasoning-row.client.spec.tsx:40-77`).
- Expansion works from either the "Think" title or the summary text (`reasoning-row.client.spec.tsx:79-96`).
- `**` emphasis markers are stripped from the summary **only**; the expanded body keeps the raw text verbatim (`reasoning-row.client.spec.tsx:98-124`: `expect(view.container.querySelector('[class*="thinkBody"]')?.textContent).toBe(text)`).
- Expanded row drops the inline summary and renders plain prose — no "IN" card (`reasoning-row.client.spec.tsx:126-140`).
- Sticky-header selector nesting only matches on an open Think row (`reasoning-row.client.spec.tsx:142-162`).
- Single-line reasoning does not get truncated by the newline cut (`chat-branch-tails.client.spec.tsx:1045-1055`).
- Interleaved text + reasoning: a reasoning block that is not the tail while the message streams renders `data-state="ok"` (`gate-branch-tails.client.spec.tsx:22-33`); the tail renders `data-state="running"` (`:59-69`).
- Empty reasoning: `emptyAssistantBlock('reasoning')` is `{ kind: 'reasoning', text: '' }` (`conversation.client.spec.ts:39`); a `block-start` + `block-end` with no deltas still yields an empty reasoning block (`partial.client.spec.ts:80-83`); empty reasoning deltas are invisible to the process projector (`conversation-nodes/turn-process.ts:48-49`, `:62-72`).
- Multiple/interleaved chunks: deltas accumulate on the reasoning lane and a delta whose previous block was text restarts the lane (`partial.client.spec.ts:16-41`).
- Very long reasoning: 100,000 reasoning chunks streamed through the real host while a live `[data-variant="think"][data-state="running"]` row stays mounted; budgets are `MAIN_THREAD_DELAY_BUDGET_MS = 250` for both main-thread delay and a scheduled interaction (`reasoning-chunks.stress.ts:18-24`, `:184-196`, `:215-227`).
- Aborted streams: an interrupted step settles as `status: 'interrupted'` with `finalNode.interrupted === true` (`conversation-node-definitions.client.spec.ts:817-843`); an interrupted tool-only assistant stays `visibility: 'visible'` (`:889-901`); an interrupted `turn/end` still fixes the answer boundary (`:390-405`); the UI adds the `已停止` chip (`coverage-tails.client.spec.tsx:32-41`) and disables branch when interrupted Think follows the final content (`chat-view.client.spec.tsx:2017-2033`).
- Turn-process folding: three process members all get `hidden="until-found"`, expand on toggle, and reveal on a `beforematch` event (`chat-view.client.spec.tsx:1341-1396`); final-step reasoning folds under `已思考` when every counter is zero (`:1582-1599`); the fold follows the persisted `compact`/`normal` mode (`:1561-1580`); it never folds while history is incomplete (`:1679-1701`), folds even off-tail (`:1601-1619`), and stays open when a member holds focus (`:1648-1677`).
- **Not about transcript reasoning**: `apps/web/tests/declared-reasoning.e2e.ts` tests the *composer* reasoning-effort picker for a hand-declared model (`reasoningEfforts: { off: null, high: 'high', max: 'ultra' }`, asserted menu `['Default','Off','High','Max']`) — it makes zero model calls and renders no Think row (`declared-reasoning.e2e.ts:1-4`, `:36-49`, `:63-89`). The reasoning transcript appearance is pinned only by the component specs and the `steer-all` ARIA snapshot, which reads `button "Think <summary>"` (`apps/web/tests/expected/steer-all/settled-expanded.expected.md:27-30`).

## Implementer notes

Keep (behavioural contract, framework-agnostic):

- Reasoning as a **collapsed-by-default disclosure inside the assistant turn**, one row per reasoning block, never auto-expanded — not even when the stream ends.
- Streaming summary = latest non-empty line with `**` stripped, right-aligned and allowed to overflow; settled summary = first line, left-aligned, ellipsised. Expand toggle reachable from both the title and the summary, state preserved across chunk appends.
- `aria-expanded` on the toggle, `role="button"` + Enter/Space handling on the row, and a visually-hidden running label; the running sweep must stop under `prefers-reduced-motion`.
- Open rows pin their header (`position: sticky; top: 0; z-index: 1`) with an opaque `bg-base` fill, and the body keeps `white-space: pre-wrap`.
- Turn-level fold: a single summary row above the process block whose label is assembled from counts (`1 tool call · 1 message · 1 subagent`) with a zero-count fallback ("Thought for a while"); process rows collapse to `hidden="until-found"` (keeps in-page find working) rather than unmounting; the answer row tightens from 16px to 8px; fold only after the turn closes with complete history.
- Independent rows (`turn-error`, `turn-max-tokens`, system prompt, user, turn tail) must stay outside the fold.
- Terminal-measure run time and usage in the turn tail, not on the reasoning row; show the elapsed clock only after ~15s of turn activity.

Do **not** copy (DSH/Cordis-specific):

- `ctx.slots.register` / `slots.inject` / keyed-node registration and the `ConversationNodeDefinition` + projector machinery (`register-node-renderers.ts:17-56`; `conversation-nodes/turn-process.ts:209-308`) — a plain React app folds the same facts in a reducer.
- Synthetic sequence anchors (`CHAT_SYNTHETIC_SEQ_OFFSETS.processControl`, `conversation-nodes/turn-process.ts:297`) and the snapshot/selector store plumbing (`stores.ts:24-43`).
- The CSS-Modules + `--dsw-*`/`--dsh-*` token layer and the font-delta axis (`--dsh-content-font-delta`); a Tailwind app needs its own scale rather than transliterated `calc(24px + var(--delta))` expressions.
- The typed locale-dictionary plumbing (`t('message.think')` etc.) — copy the copy, not the i18n seat. Note `row.running` resolves from the conversation locale, not `ui-chat`'s dictionary (`ui-conversation/src/client/locales.ts:252`).
- `useSearchableHidden`'s browser-find integration is optional; `hidden="until-found"` plus `beforematch` is the portable part (`searchable-hidden.ts:14-29`).
- The `contain: size layout` collapsed-height trick (`ReasoningRow.module.css:6-9`) is a perf micro-optimisation; visually a fixed 24px line is the contract.
