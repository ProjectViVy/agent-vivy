## Fixed contracts

### Operation identity and results

Replace RequestDigest/ArgumentsDigest with private RequestArguments []byte. Retain MiddlewareInputArguments/EffectiveArguments, RunID/OperationID/ToolName, claim owner/state, Result/Failure and timestamps. Add OutcomeStatus/OutcomeReason/OutcomeEffects.

Lookup compares tool name and original raw bytes; reordered keys or whitespace are different retry identities. Repeated admission compares all three argument byte sets. Execute rereads durable binding before claim or replay. Missing original input yields source_binding_unavailable before identity comparison/claim/replay; Get remains available for diagnosis. Every new argument set is nonempty valid JSON within 1 MiB and is independently copied.

Produce domain.ToolOperationOutcome{Result, Failure, Status, Reason, Effects string}. Replace the existing completion method with:

```go
CompleteToolOperation(context.Context, domain.RunID, string, string, domain.ToolOperationOutcome) (domain.ToolOperation, domain.RunEvent, error)
```

The coordinator execution callback returns (domain.ToolOperationOutcome,error); its Eino-facing result remains (string,error). Complete state, all outcome fields and the Journal append commit atomically. Repeated completion compares every outcome field. Status is success/recoverable/refused/fatal. Recoverable/refused use existing reasons; other reasons are empty. Effects is not_executed/none/unknown; absence of affirmative evidence of no effects means unknown. New noncompleted rows carry empty (non-NULL) outcome values; completed bound rows require valid complete classifications. NULL fields are reserved for converted unbound history.

Native interrupts and cancellation/deadlines retain control-flow semantics. Unknown claimed effects never auto-reclaim. A failed completion does not return ordinary success. Live errors preserve their cause chain. Replay restores typed classification from the row, including when Eino reuses completed sibling output without dispatching the adapter; do not infer categories from text or use nudge memory as durable authority.

### Approval v2

Use private vivy.tool-approval-proposal/v2 with intended_arguments and the existing provider bytes. Helper signatures:

```go
bindToolApprovalProposal(json.RawMessage, json.RawMessage) (json.RawMessage,error)
unbindToolApprovalProposal(json.RawMessage) (json.RawMessage,json.RawMessage,error)
```

Canonicalize intended arguments using UseNumber decode and JSON encode; reject invalid/trailing JSON and retain numeric literals. Key order/insignificant whitespace may differ; do not invent numeric equivalence. Compare current invocation, native interrupt state, private approval and existing Run/call/tool/resume-target/checkpoint ownership. v1/bare/unknown/missing bindings fail explicitly, with no fallback. Unapproved siblings remain interrupted and fresh calls retain current Policy evaluation. Work and other non-row approvals keep their existing owner.

### Conversion and startup boundary

All baseline operation rows get NULL RequestArguments and NULL new outcome fields. Never recover original input from effective/checkpoint/preview bytes or classify historical Result/Failure text. Preserve original state, claim owner, result/failure and times.

The existing Apply path currently performs CREATE/backfill before format refusal. Add a read-only preflight at that shared runner entry before any writes: pristine namespace may initialize; recognized old sources through 035 require explicit upgrade; unknown/partial/unlisted lineages fail unsupported_source_format. A numeric 036 alone is not target evidence: require the known migration name/contiguous metadata and actual required operation columns. Retain current checksum metadata handling in this intermediate Story; D12 owns its replacement. Reuse ApplyManifest for explicitly constructed disposable target fixtures; do not add a second runner.

Keep D03's paired schema migration separate from approval settlement. Supply approval conversion as a target-transaction SQL fragment under the migration owner's transition resources, outside the ordinary runtime embed glob. D14 combines it with D08's checkpoint/interaction/Run fragment in one target transaction.

There is no universal consumed marker. Conservatively expire pending and approved/possibly-unconsumed authority on baseline nonterminal Runs with upgrade_recovery_required; retain terminal Run approval history and every operation effect fence. Revocation does not assert that no effect happened. Add no consumed-state registry and parse no old opaque checkpoint.

D03 does not claim final metadata, one-transaction final initialization, full D08 conversion or a distributable upgrader. D12/D14 retain these final-release gates. Unknown effects remain fenced even when checkpoints cannot resume.
